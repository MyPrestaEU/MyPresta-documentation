# European Central Bank currency rates

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.5.x, 1.6.x, 1.7.x, 8.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for fetching external data, which are almost universally available on modern hosting environments.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, click “Configure” to access the module’s main settings. This is where you control how and when your currency rates are updated.

The configuration screen will typically present a form with options to enable/disable the module’s functionality and potentially a way to manually trigger an update or set up a cron job.

**Cronjob URL:**

- **What this setting does:** This displays a unique URL that, when accessed, triggers the module to fetch the latest currency rates from the European Central Bank and update them in your PrestaShop store. This is the core mechanism for automated updates.
- **Effect of changing this setting:** This is a read-only URL generated by the module. You don’t change it directly.
  - *When used in a cron job:* Your currency rates will be automatically updated at regular intervals without any manual intervention.
  - *When not used:* Rates will only update if you manually click the “Update now” button (if available) or if PrestaShop’s default, less reliable, currency update mechanism is used.
- **Recommended value:** Copy this URL and set it up as a cron job on your hosting server. This is the most efficient and reliable way to keep your rates current.
- **Merchant scenario / example:** You want your currency rates to update every day at 3 AM. You copy this URL and add it to your hosting control panel’s cron job scheduler, set to run daily at 3 AM.

**Update now button (if present):**

- **What this setting does:** This is a manual trigger to immediately fetch and update all currency rates from the ECB.
- **Effect of changing this setting:**
  - *When clicked:* The module will instantly connect to the ECB, retrieve the latest exchange rates, and apply them to your store’s currencies. This is useful for immediate updates or testing.
- **Recommended value:** Use this for initial setup testing or if you need an immediate update outside of your scheduled cron jobs. For regular updates, rely on the cron job.
- **Merchant scenario / example:** You’ve just installed the module and want to ensure it’s working correctly. You click “Update now” and then check your currency rates in PrestaShop to confirm they’ve changed.

**General Module Configuration (if present, e.g., Enable/Disable):**

- **What this setting does:** This is a standard PrestaShop module switch to activate or deactivate the module’s core functionality.
- **Effect of changing this setting:**
  - *When enabled:* The module will be active, and its cron job URL will function, allowing for automated currency updates.
  - *When disabled:* The module will not perform any updates, and the cron job URL will not work. Your currency rates will not be updated by this module.
- **Recommended value:** **YES** (Enabled) to ensure your currency rates are automatically updated.
- **Merchant scenario / example:** You want the module to manage your currency rates, so you ensure it’s enabled. If for some reason you wanted to temporarily stop automatic updates, you would disable it.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My currency rates aren’t updating automatically. What should I check?**
A:

1. **Cron Job Setup:** The most common issue is an incorrectly configured cron job. Double-check the URL you’ve used in your hosting panel and ensure the schedule is active and correct.
2. **Module Enabled:** Make sure the “European Central Bank currency rates” module is enabled in your PrestaShop Back Office (**Modules > Module Manager**).
3. **PHP Version:** Ensure your PHP version is within the module’s compatibility range (PHP 5.6 - 8.5).
4. **Server Logs:** Check your server’s cron job logs (if your host provides them) for any errors when the cron job attempts to run.
5. **Manual Update:** Try clicking the “Update now” button on the module’s configuration page. If this works, the issue is definitely with your cron job setup.

**Q: The rates updated, but they seem incorrect or different from what I expected.**
A:

1. **ECB Source:** This module fetches rates directly from the European Central Bank. These are official interbank rates, which might differ slightly from consumer rates you see on Google or other financial sites due to bank fees, spreads, or different update times.
2. **Base Currency:** Ensure your PrestaShop’s default currency is correctly configured. The module updates rates relative to the base currency.
3. **Cache:** Clear your PrestaShop cache (**Advanced Parameters > Performance**) after an update to ensure you’re seeing the freshest data.

**Q: Does this module work with custom themes?**
A: Yes, absolutely. This module works in the background to update data (currency rates) in your database. It does not output any visual elements or modify your theme’s design, so it is fully compatible with any PrestaShop theme.

**Q: How often should I update the currency rates?**
A: For most e-commerce stores, updating daily is sufficient. If you deal with high-value items or operate in highly volatile markets, you might consider updating twice a day. The ECB typically publishes its reference rates once a day, around 16:00 CET.

**Q: I see a “500 Internal Server Error” when trying to access the cron job URL directly.**
A: This usually indicates a PHP error. Check your server’s PHP error logs for more specific details. Common causes could be incorrect file permissions, a missing PHP extension, or a conflict with another module. Contact your hosting provider or a developer with the error log details.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

This section provides a detailed technical overview for developers and webmasters.

### 4.1 Architecture Overview

The “European Central Bank currency rates” module (`ecbrates`) is a lightweight PrestaShop module primarily designed to automate the update of `ps_currency` exchange rates. It follows a simple design pattern:

- A single main module file (`cronjob.php`) handles installation, uninstallation, and the core logic for fetching and updating currency rates.
- The module exposes a `getContent()` method for its Back Office configuration, which renders a basic template.
- The core functionality is triggered via a direct call to the module’s `cronjob.php` file, typically by a server-side cron job, bypassing standard PrestaShop front/admin controller routing for efficiency.

### 4.2 Controllers (`controllers/`)

This module does not utilize standard PrestaShop Front-Office or Back-Office Admin Controllers. Its core update logic is directly accessible via the `cronjob.php` file, which acts as a standalone script when called via the cron URL.

### 4.3 Core Classes & Models (`classes/`)

This module does not define any custom classes or extend `ObjectModel`. All logic is contained within the main `ecbrates/cronjob.php` file. It directly interacts with PrestaShop’s core `Currency` class and `Configuration` class.

### 4.4 JavaScript Assets (`views/js/`)

This module does not include any custom JavaScript files.

### 4.5 CSS Stylesheets (`views/css/`)

This module does not include any custom CSS files.

### 4.6 Smarty Template Structure (`views/templates/`)

- **Admin templates (`views/templates/admin/`)**:
  - `ecbrates/views/admin.tpl`: This template is rendered by the `getContent()` method of the main module file. It displays the module’s configuration form, including the cron job URL and potentially a manual update button. It’s a simple template for the module’s settings.

### 4.7 Database Schema & Hooks Map

- **Database Tables**:

  - This module does not create any custom database tables.
  - It interacts with the standard PrestaShop `ps_currency` table to update the `conversion_rate` column for active currencies.
  - It stores its configuration (e.g., module enabled status) in the `ps_configuration` table, using keys like `ECBRATES_LAST_UPDATE` or similar, though specific keys are not explicitly detailed in the provided information.
- **Registered Hooks Table**:
  This module does not explicitly register to any standard PrestaShop hooks in the traditional sense (e.g., `displayHeader`, `actionValidateOrder`) for its core functionality. Its primary mechanism is a direct call to its `cronjob.php` file.

  However, as a PrestaShop module, it implicitly uses:

  | Hook Name | Execution Timing | Technical Purpose |
  | --- | --- | --- |
  | `install()` | During module installation | Creates configuration entries, potentially sets initial rates. |
  | `uninstall()` | During module uninstallation | Cleans up configuration entries. |
  | `getContent()` | When accessing module configuration in BO | Renders the module’s configuration form. |

  The module’s core functionality (fetching and updating rates) is triggered by direct HTTP access to `cronjob.php`, not by a PrestaShop hook.
