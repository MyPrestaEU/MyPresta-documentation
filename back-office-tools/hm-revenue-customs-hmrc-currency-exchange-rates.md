# HM Revenue & Customs (HMRC) - currency exchange rates

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for fetching external data, which are standard on most hosting environments.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, clicking “Configure” will take you to the main configuration screen for the HMRC Currency Rates module. This is where you’ll set up how the module fetches and applies the official exchange rates.

The configuration page will present you with the following key information and settings:

#### **Cron Job URL**

- **What this setting does:** This is a special web address (URL) that, when visited, triggers the module to fetch the latest HMRC exchange rates and update them in your PrestaShop store. It’s designed to be run automatically by a “cron job” on your server.
- **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module.
- **Recommended value:** Copy this URL exactly as it appears.
- **Merchant scenario / example:** You will need this URL to set up an automated task (cron job) on your web hosting server. This task will visit the URL at a scheduled time (e.g., once a day or once a month) to ensure your rates are always up-to-date without you having to manually click anything.

#### **Cron Job Command (for Linux/Unix servers)**

- **What this setting does:** This is a command-line instruction that achieves the same result as visiting the Cron Job URL, but it’s specifically formatted for direct use in a server’s cron job scheduler (often found in your hosting control panel like cPanel or Plesk). It uses `wget` or `curl` to silently request the URL.
- **Effect of changing this setting:** You cannot change this command directly. It’s generated by the module.
- **Recommended value:** Copy this command exactly as it appears.
- **Merchant scenario / example:** If your hosting provider uses Linux/Unix servers (which most do), you’ll use this command to set up your automated cron job. This is generally more reliable than relying on web-based cron services.

#### **Last Update Status**

- **What this setting does:** This section displays information about when the module last successfully fetched and updated the HMRC rates. It will show the date and time of the last update.
- **Effect of changing this setting:** This is an informational display only; you cannot change it.
- **Recommended value:** Monitor this to ensure your cron job is running correctly and the rates are being updated regularly.
- **Merchant scenario / example:** If you set up your cron job to run daily, you should see the “Last Update Status” change daily, confirming that the module is working as expected. If it’s not updating, it indicates an issue with your cron job setup.

#### **“Update Now” Button**

- **What this setting does:** This button allows you to manually trigger the rate update process immediately, directly from the module configuration page.
- **Effect of changing this setting:** Clicking this button will instantly fetch the latest HMRC rates and apply them to your store’s currencies.
- **Recommended value:** Use this button for initial testing after installation, or if you need to force an immediate update outside of your scheduled cron job.
- **Merchant scenario / example:** After installing the module, click “Update Now” to see if it fetches the rates correctly and to populate your store with the latest HMRC rates before your first scheduled cron job runs.

#### **Important Note on Cron Jobs:**

The core functionality of this module relies on a **cron job** being set up on your web server. A cron job is a time-based job scheduler in Unix-like computer operating systems. It allows users to schedule jobs (commands or scripts) to run periodically at fixed times, dates, or intervals.

**How to set up a cron job (general steps):**

1. **Access your Hosting Control Panel:** Log in to your cPanel, Plesk, or other hosting control panel.
2. **Find “Cron Jobs” or “Scheduled Tasks”:** Look for a section usually named “Cron Jobs,” “Scheduled Tasks,” or “Automation.”
3. **Add a New Cron Job:**
   - **Frequency:** Set the frequency. For HMRC rates, monthly is usually sufficient (e.g., “Once a month” on the 1st day of the month). Some merchants prefer daily for extra safety, but HMRC rates are monthly.
   - **Command:** Paste the “Cron Job Command” provided by the module into the command field.
   - **Email:** You can usually specify an email address to receive output from the cron job. This is useful for troubleshooting if the job fails.
4. **Save:** Save the cron job.

If you are unsure how to set up a cron job, please contact your hosting provider’s support team and provide them with the “Cron Job Command” from the module’s configuration page, asking them to set it up to run monthly (or daily, as per your preference).

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My exchange rates aren’t updating. What should I do?**
A: The most common reason for this is an incorrectly set up cron job.
1. **Check your cron job setup:** Log into your hosting control panel (cPanel, Plesk, etc.) and verify that the cron job is correctly configured using the “Cron Job Command” provided by the module. Ensure the frequency is set as desired (e.g., monthly or daily).
2. **Test manually:** Go to the module’s configuration page in your PrestaShop back office and click the “Update Now” button. If this works, the issue is definitely with your cron job setup. If it doesn’t work, there might be a server-side issue preventing the module from fetching data (e.g., firewall, cURL issues).
3. **Contact your host:** If you’re unsure about cron jobs, provide your hosting support with the “Cron Job Command” and ask them to set it up for you.

**Q: Does this module affect the prices customers see on my website?**
A: Yes, indirectly. The module updates the underlying exchange rates in PrestaShop. If your store allows customers to switch between currencies, the prices displayed in those foreign currencies will reflect the updated rates. However, the module’s primary purpose is for *internal* accounting and tax compliance, not necessarily for dynamic front-end pricing strategies.

**Q: What if HMRC changes its exchange rate publication method?**
A: MyPresta.eu regularly monitors changes to external services like HMRC. If HMRC alters its data source or format, we will release an update to the module to ensure continued compatibility. Always keep your modules updated to their latest versions.

**Q: Can I use this module if my base currency is not GBP?**
A: While the module fetches HMRC rates, its primary benefit is for UK VAT compliance, which typically assumes GBP as the reporting currency. If your base currency is not GBP, the module will still update the exchange rates for other currencies relative to your base currency, but you’ll need to understand how this interacts with your specific tax reporting obligations. For UK VAT, having GBP as your default currency is generally recommended.

**Q: I’m seeing an error message when trying to update rates manually.**
A: This could indicate a few things:
1. **Server connectivity:** Your server might be unable to connect to the HMRC website to fetch the data. This could be due to a firewall, network issue, or temporary HMRC server downtime.
2. **PHP extensions:** Ensure standard PHP extensions like `cURL` and `JSON` are enabled on your server.
3. **Module permissions:** Check that the module files have correct read/write permissions.
If the issue persists, contact MyPresta.eu support with the exact error message.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

This section provides a technical overview for developers and webmasters responsible for maintaining or extending the PrestaShop store.

### 4.1 Architecture Overview

The `hmrcrates` module is a straightforward PrestaShop module designed to fetch and update currency exchange rates from the HMRC website. It leverages PrestaShop’s module architecture, primarily using the `Module` class for installation/uninstallation and `ModuleFrontController` for handling cron job requests. The core logic resides within the main module file, `cronjob.php`, which also acts as the primary entry point for configuration and the cron execution. It does not use `ObjectModel` as it directly manipulates existing `Currency` objects.

### 4.2 Controllers (`controllers/`)

- **Front-Office Controllers**:

  - `controllers/front/cronjob.php`
    - **Class name & parent class**: `HmrcratesCronjobModuleFrontController` extending `ModuleFrontController`.
    - **Responsibility**: This controller is the public endpoint for the cron job. When accessed via its URL (e.g., `yourstore.com/module/hmrcrates/cronjob`), it triggers the `processUpdateRates()` method in the main `hmrcrates` module. It’s designed to be called by external cron services or server-side cron jobs. It outputs a simple success or error message.
  - `controllers/front/index.php`
    - **Class name & parent class**: `HmrcratesIndexModuleFrontController` extending `ModuleFrontController`.
    - **Responsibility**: This is a placeholder controller, typically used to provide a default entry point for a module if no specific action is requested. In this module’s context, it likely serves no direct functional purpose other than providing a default route if `cronjob.php` is not explicitly called. It might redirect or simply display a blank page.
- **Back-Office Admin Controllers**:

  - This module does not utilize dedicated `AdminController` files. All back-office configuration is handled directly within the `getContent()` method of the main module class.

### 4.3 Core Classes & Models (`classes/`)

This module does not define any custom classes within the `classes/` directory. The core logic for fetching and updating rates is encapsulated within the main module file, `hmrcrates/cronjob.php`. It directly interacts with PrestaShop’s built-in `Currency` class to update exchange rates.

### 4.5 CSS Stylesheets (`views/css/`)

### 4.7 Database Schema & Hooks Map

- **Database Tables**:

  - This module does not create any custom SQL tables.
  - It stores its configuration settings (e.g., `HMRCRATES_LAST_UPDATE`) in the standard PrestaShop `ps_configuration` table.
  - It updates the `exchange_rate` column in the `ps_currency` table for relevant currencies.
- **Registered Hooks Table**:
  This module does not explicitly register any front-office display hooks (like `displayHeader`, `displayRightColumn`, `displayFooter`) as its functionality is purely backend-oriented. Its primary “hook” is the `action` hook triggered by the `ModuleFrontController` for the cron job.
