# Database Optimization Pro

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.5.x, 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically sufficient. Access to your hosting control panel (cPanel, Plesk, etc.) to set up cron jobs is highly recommended for the module’s full automation capabilities.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, clicking “Configure” will take you to the main configuration screen for Database Optimization Pro. This is where you’ll set up the automatic cleanup and get the necessary information for your cron job.

The configuration page is straightforward and provides the essential tools for managing your database optimization.

#### **Cron Job URL**

- **What this setting does:** This is the unique web address (URL) that, when visited, triggers the database optimization process. It’s designed to be called by an automated system (a cron job) rather than a human browsing to it.
- **Effect of changing this setting:** You cannot change this URL directly from the module configuration. It’s automatically generated by the module.
- **Recommended value:** Copy this URL exactly as it appears. You will need it to set up your cron job on your hosting server.
- **Merchant scenario / example:** You will copy this URL and paste it into the cron job setup interface provided by your web host (e.g., cPanel, Plesk, or a custom cron job manager). This tells your server “every X hours/days, visit this URL to clean my database.”

#### **Run Optimization Now**

- **What this setting does:** This is a manual trigger to run the database optimization process immediately. It performs the same cleanup actions as the cron job URL, but on demand.
- **Effect of changing this setting:**
  - *When clicked:* The module will instantly begin cleaning your database. You will see a confirmation message once it’s complete.
- **Recommended value:** Use this button for initial testing after installation, or if you need to perform an immediate cleanup outside of your scheduled cron jobs.
- **Merchant scenario / example:** You’ve just installed the module and want to see it in action, or you’ve made a lot of changes to your store (e.g., imported many products) and want to clean up immediately without waiting for the next scheduled cron job.

#### **Setting up the Cron Job**

This is the most crucial part of automating your database optimization. A cron job is a time-based job scheduler in Unix-like computer operating systems. It allows you to schedule commands or scripts to run automatically at a specified time or interval.

**Steps to set up a cron job (general guide - specific steps may vary by host):**

1. **Log in to your Hosting Control Panel:** This is usually cPanel, Plesk, or a custom control panel provided by your host.
2. **Find “Cron Jobs” or “Scheduled Tasks”:** Look for a section related to cron jobs, often under “Advanced” or “Tools.”
3. **Add a New Cron Job:**
   - You’ll typically need to specify the frequency (e.g., once a day, once a week). A good starting point is once a day or once every few days.
   - You’ll need to provide the “Command” or “URL to call.” This is where you paste the **Cron Job URL** you copied from the module’s configuration page.
   - The command format often looks like this:

     Terminal window

     ```
     wget -q -O /dev/null "YOUR\_CRON\_JOB\_URL\_HERE"
     ```

     Replace `"YOUR_CRON_JOB_URL_HERE"` with the exact URL from the module. The `wget` command fetches the URL, and `-q -O /dev/null` ensures it runs quietly without saving the output, which is ideal for background tasks.
4. **Save the Cron Job:** Confirm your settings to activate the scheduled task.

**Example Cron Job Frequencies:**

- **Once a day (e.g., 3 AM):**
  `0 3 * * * wget -q -O /dev/null "YOUR_CRON_JOB_URL_HERE"`
- **Once a week (e.g., every Sunday at 4 AM):**
  `0 4 * * 0 wget -q -O /dev/null "YOUR_CRON_JOB_URL_HERE"`

Choose a time when your store typically has low traffic to minimize any potential (though usually negligible) impact on performance during the cleanup.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: I’ve set up the cron job, but I don’t see any difference in my store’s speed.**
A: Database optimization provides incremental improvements. If your store was already relatively fast, the change might not be dramatic.
- **Check your cron job:** Ensure it’s correctly configured on your host and running. Some hosts provide logs for cron job execution.
- **Run manually:** Click “Run Optimization Now” in the module config. If this works, the issue is likely with your cron job setup.
- **Clear Smarty Cache:** Sometimes visual changes or speed improvements require clearing PrestaShop’s cache. Go to **Advanced Parameters > Performance**, scroll down to “Clear cache” and click “Clear cache.”

**Q: What data does this module actually clean?**
A: The module targets various types of temporary and obsolete data that accumulate in your database, such as:
- Old guest carts that were never converted to orders.
- Expired sessions.
- Old log entries (access logs, page-not-found logs).
- Temporary files and cache data stored in the database.
It does NOT delete customer data, orders, products, or any essential store information.

**Q: Can this module break my store?**
A: This module is designed to safely remove only non-essential, temporary, or obsolete data. It does not touch critical store data like products, orders, customers, or categories. However, as with any module that interacts with your database, it’s always recommended to have a recent backup before installation and configuration.

**Q: My hosting provider doesn’t support cron jobs, or I’m having trouble setting it up.**
A: If you cannot set up a cron job, you can still use the module by manually clicking the “Run Optimization Now” button in the module’s configuration page whenever you feel your store needs a cleanup (e.g., once a week or once a month). While not automatic, it still provides the benefits of database optimization. Contact your hosting provider’s support for assistance with cron job setup; they are usually very helpful with this common task.

**Q: Does this module affect my SEO?**
A: Indirectly, yes. Faster page loading times are a positive ranking factor for search engines like Google. By improving your site’s speed, this module contributes to a better user experience, which can positively influence your SEO performance.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

This section is strictly for developers, store webmasters, and technical agencies maintaining or extending the store.

### 4.1 Architecture Overview

The `Database Optimization Pro` module is a lightweight administration tool primarily focused on database maintenance. Its core functionality revolves around executing a series of SQL queries to clean up non-essential data. The “Pro” aspect introduces an automated mechanism via a front-office controller designed to be triggered by a cron job, allowing for scheduled, unattended optimization. It adheres to PrestaShop’s module structure, utilizing a main module file for installation/configuration and a dedicated front controller for the cron execution.

### 4.2 Controllers (`controllers/`)

- **Front-Office Controllers**:

  - `controllers/front/CronCleaner.php`
    - **Class Name**: `DboptimizationproCronCleanerModuleFrontController`
    - **Parent Class**: `ModuleFrontController`
    - **Responsibility**: This is the critical controller for the cron job functionality. When accessed, it executes the database cleanup logic. It’s designed to be called externally (e.g., by `wget` via a cron job) and does not render a visible page to the user. It performs the actual database optimization queries.
  - `controllers/front/index.php`
    - **Class Name**: (Not a class, typically an empty file or a redirect)
    - **Responsibility**: This file is often included in PrestaShop modules to prevent directory listing when browsing `yourstore.com/modules/dboptimizationpro/controllers/front/`. It typically contains a simple `header('Location: ../../../index.php'); exit;` or similar to redirect to the homepage, ensuring security.
- **Back-Office Admin Controllers**:

  - No dedicated admin controllers are present. All back-office configuration is handled directly within the main module file’s `getContent()` method.

### 4.3 Core Classes & Models (`classes/`)

No custom classes or `ObjectModel` definitions are present in the `classes/` directory. The module’s logic is encapsulated within the main module file (`dboptimizationpro/cronjob.php`) and the `CronCleaner` front controller. Database interactions are likely direct SQL queries executed via `Db::getInstance()->execute()`.

### 4.4 JavaScript Assets (`views/js/`)

No custom JavaScript files are found in the module archive. The module’s functionality is server-side.

### 4.5 CSS Stylesheets (`views/css/`)

No custom CSS files are found in the module archive. The module’s configuration page uses standard PrestaShop back-office styling.

### 4.6 Smarty Template Structure (`views/templates/`)

No custom Smarty template files (`.tpl`) are found in the module archive. The module’s configuration form is rendered directly within the `getContent()` method of the main module file using PrestaShop’s helper forms or raw HTML.

### 4.7 Database Schema & Hooks Map

- **Database Tables**:

  - The module does not create any custom database tables.
  - It interacts with existing PrestaShop tables to delete obsolete data (e.g., `ps_cart`, `ps_connections`, `ps_log`, `ps_guest`, `ps_pagenotfound`).
  - Configuration settings (like the cron job URL or a flag indicating last run) are stored in the `ps_configuration` table, typically with keys prefixed by `DBOPTIMIZATIONPRO_`.
- **Registered Hooks Table**:
  The module does not explicitly register any front-office hooks (e.g., `displayHeader`, `displayRightColumn`, `displayFooter`) to display content. Its primary interaction with PrestaShop’s hook system is for module installation/uninstallation and potentially for back-office menu integration (though not explicitly listed as an admin controller, the module itself appears in the Modules list).

  The module’s core functionality is triggered by:

  - Accessing the `getContent()` method in the back office for manual configuration and execution.
  - Accessing the `CronCleaner` front controller via an external cron job.
