#### 2.1.1 CRON URL

- **What this setting does:** This is a unique web address (URL) that, when visited, triggers the module to fetch the latest exchange rates from the Bank of Latvia and update them in your PrestaShop store. It’s designed to be called automatically by a “cron job” on your server.
- **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module. Copying this URL is essential for setting up the automated updates. If you don’t set up a cron job using this URL, exchange rates will not be automatically updated.
- **Recommended value:** Copy this URL exactly as it appears.
- **Merchant scenario / example:** You will copy this URL and paste it into your hosting control panel’s “Cron Jobs” section (e.g., cPanel, Plesk, or a similar interface) to schedule daily updates.

#### 2.1.2 Spread (%)

- **What this setting does:** This allows you to add a percentage “buffer” or margin to the official exchange rates. When the module fetches a rate, it will increase it by this percentage before saving it to your store. This helps protect your profit margins against currency fluctuations and transaction fees.
- **Effect of changing this setting:**
  - *When set to 0:* The module will use the exact exchange rates provided by the Bank of Latvia. Your prices will reflect the official rates directly.
  - *When set to a positive value (e.g., 2%):* The exchange rates in your store will be 2% higher than the official rates. This means if a product costs 100 EUR and the official rate to USD is 1.10, with a 2% spread, the module will use a rate of 1.122 (1.10 \* 1.02), making the USD price 112.20.
- **Recommended value:** This depends on your business model, payment gateway fees, and desired profit margins. A common starting point might be 0.5% to 2% to cover transaction costs and minor fluctuations.
- **Merchant scenario / example:** If your payment processor charges a 1% fee for international transactions, setting a spread of 1.5% could help you absorb that cost and still maintain your desired profit margin.

#### 2.1.3 Update Frequency

- **What this setting does:** This setting determines how often the module *should* attempt to update the exchange rates. While the cron job (see CRON URL) is what actually triggers the update, this setting acts as a safeguard to prevent too frequent updates, which might be unnecessary or even problematic for some hosting environments.
- **Effect of changing this setting:**
  - *When set to “Daily”:* The module will only process an update once every 24 hours, even if the cron job runs more frequently.
  - *When set to “Hourly”:* The module will process an update once every hour.
  - *When set to “Every 15 minutes”:* The module will process an update every 15 minutes.
- **Recommended value:** “Daily” is usually sufficient for most e-commerce stores, as official exchange rates typically don’t fluctuate drastically within minutes. If you have very high-value items or operate in extremely volatile markets, “Hourly” might be considered.
- **Merchant scenario / example:** You set your cron job to run every 6 hours, but you set the “Update Frequency” here to “Daily.” The module will only perform an actual rate update once within a 24-hour period, even though the cron job attempts to trigger it more often. This prevents unnecessary API calls and resource usage.

#### 2.1.4 Enable Module

- **What this setting does:** This is a simple on/off switch for the module’s core functionality.
- **Effect of changing this setting:**
  - *When enabled (YES):* The module will actively fetch and update exchange rates according to your settings and cron job schedule.
  - *When disabled (NO):* The module will stop fetching and updating exchange rates. Your store will continue to use the last known rates, or PrestaShop’s default behavior for rate updates if you have other mechanisms in place.
- **Recommended value:** “YES” to ensure automated currency updates.
- **Merchant scenario / example:** You might temporarily disable the module if you need to perform maintenance on your store or if you decide to manage exchange rates manually for a short period. Remember to re-enable it afterward.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My exchange rates are not updating. What should I do?**
A:

1. **Check your Cron Job:** The most common reason is an incorrectly set up or missing cron job on your hosting server. Double-check that you’ve copied the exact CRON URL from the module’s configuration page and that your cron job is scheduled to run.
2. **Module Enabled?** Ensure the “Enable Module” switch on the configuration page is set to “YES.”
3. **Update Frequency:** Check the “Update Frequency” setting. If your cron job runs every hour but the frequency is set to “Daily,” it will only update once a day.
4. **PrestaShop Cache:** Sometimes, clearing your PrestaShop cache (under **Advanced Parameters > Performance**) can help refresh displayed data, though it’s less likely to affect the backend rate updates.

**Q: Can I manually override an exchange rate after the module updates it?**
A: Yes, you can. The module updates the rates in PrestaShop’s standard currency management system. If you go to **International > Currencies** in your Back Office, you can manually edit the exchange rate for any currency. However, be aware that the module will overwrite your manual changes the next time the cron job runs and triggers an update.

**Q: What happens if the Bank of Latvia’s service is temporarily unavailable?**
A: The module is designed to fetch rates from an external source. If the Bank of Latvia’s service is down or unreachable, the module will likely fail to retrieve new rates. In such cases, your store will continue to use the *last successfully updated* exchange rates. It will not revert to default or incorrect rates. Once the service is restored, the next cron job run will update the rates again.

**Q: Does this module create new currencies in my store?**
A: No, this module only updates the exchange rates for currencies you have *already enabled* in your PrestaShop store (under **International > Currencies**). You must first add and enable the desired currencies in PrestaShop’s standard settings for this module to manage their rates.

**Q: My custom theme doesn’t display prices correctly after updates.**
A: This module only changes the underlying exchange rates. If prices are displayed incorrectly, it’s highly unlikely to be a direct module issue.

1. **Clear Smarty Cache:** Go to **Advanced Parameters > Performance** and click “Clear cache.”
2. **Theme Compatibility:** Ensure your custom theme is fully compatible with your PrestaShop version.
3. **Custom Code:** If your theme has custom code for price display, it might not be correctly interpreting PrestaShop’s updated currency rates. Consult your theme developer or a PrestaShop expert.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

### 4.1 Architecture Overview

The “Bank of Latvia (Latvijas Banka) - currency exchange rates” module (`lbrates`) is a lightweight PrestaShop module primarily designed to automate currency exchange rate updates. It follows a simple MVC pattern where the main module file (`cronjob.php`) acts as the primary controller for configuration and the front controller (`cronjob.php`) handles the actual rate fetching logic. It leverages PrestaShop’s `Currency` and `Configuration` classes to manage rates and settings. The module is driven by external cron job calls, making it an asynchronous background process.

### 4.2 Controllers (`controllers/`)

- **Front-Office Controllers**:

  - `lbrates/controllers/front/cronjob.php`
    - Class name: `LbratesCronjobModuleFrontController`
    - Parent class: `ModuleFrontController`
    - Responsibility: This controller is the core of the module’s functionality. It is designed to be called by an external cron job. When accessed, it fetches the latest Euro reference rates from the Bank of Latvia’s official API, applies the configured spread, and updates the exchange rates for all active currencies in the PrestaShop database. It also handles logging and prevents too frequent updates based on the `PS_LBRATES_LAST_UPDATE` configuration key.
  - `lbrates/controllers/front/index.php`
    - Class name: `LbratesIndexModuleFrontController`
    - Parent class: `ModuleFrontController`
    - Responsibility: This is a standard empty `index.php` file often included in PrestaShop module front controller directories to prevent directory listing. It does not contain any functional logic.
- **Back-Office Admin Controllers**:

  - None. All administration is handled directly within the main module file’s `getContent()` method.

### 4.3 Core Classes & Models (`classes/`)

- None. The module directly interacts with PrestaShop’s core `Currency` and `Configuration` classes.

### 4.4 JavaScript Assets (`views/js/`)

- None. The module does not use any custom JavaScript.

### 4.5 CSS Stylesheets (`views/css/`)

### 4.6 Smarty Template Structure (`views/templates/`)

- **Admin templates (`views/templates/admin/`)**:

This includes fields for the CRON URL, Spread, Update Frequency, and the Enable/Disable switch. It uses standard PrestaShop form helpers and styling.

### 4.7 Database Schema & Hooks Map

- **Database Tables**:

  - The module does not create any custom SQL tables.
  - It stores its configuration settings in the `ps_configuration` table:
    - `PS_LBRATES_SPREAD`: Stores the configured percentage spread.
    - `PS_LBRATES_UPDATE_FREQUENCY`: Stores the configured update frequency (e.g., daily, hourly).
    - `PS_LBRATES_LAST_UPDATE`: Stores the timestamp of the last successful update to prevent too frequent calls.
    - `PS_LBRATES_ENABLED`: Stores the module’s enabled/disabled status.
  - It updates the `exchange_rate` column in the `ps_currency` table for active currencies.
- **Registered Hooks Table**:

  - The module does not register any traditional display hooks (`displayHeader`, `displayFooter`, etc.) in the front office. Its primary function is background processing.
  - It implicitly uses the `actionUpdateCurrency` hook (or similar internal mechanisms) by directly modifying currency exchange rates, but it doesn’t explicitly register to it.
  - The module’s `install()` method would register the module itself within PrestaShop’s module system, making its configuration accessible.
