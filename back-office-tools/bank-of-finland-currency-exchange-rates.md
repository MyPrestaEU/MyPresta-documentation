# Bank of Finland - currency exchange rates

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for fetching external data. Your hosting environment must also support CRON jobs for automated updates.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, click “Configure” to access the module’s settings. This is where you’ll define how the exchange rates are updated and applied.

#### **1. CRON URL**

- **What this setting does:** This is a unique web address (URL) that, when visited, triggers the module to fetch the latest exchange rates from the Bank of Finland and update them in your PrestaShop store.
- **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module. This URL is crucial for setting up an automated task (CRON job) on your web server.
- **Recommended value:** Copy this URL exactly as it appears.
- **Merchant scenario / example:** You will provide this URL to your hosting provider or use it in your hosting control panel (e.g., cPanel, Plesk) to set up a CRON job. This ensures that your exchange rates are updated automatically, for example, once a day, without you having to manually click anything.

#### **2. CRON job setup instructions**

- **What this setting does:** This section provides instructions on how to set up the CRON job using the URL provided above. A CRON job is a time-based job scheduler in Unix-like computer operating systems. It allows you to schedule commands or scripts to run automatically at specified intervals.
- **Effect of changing this setting:** This is an informational section; you don’t change anything here. Following these instructions correctly ensures your exchange rates are updated automatically.
- **Recommended value:** Read and follow these instructions carefully.
- **Merchant scenario / example:** Your hosting provider’s control panel (like cPanel) will have a “Cron Jobs” or “Scheduled Tasks” section. You’ll typically add a new cron job, specify the frequency (e.g., once a day at 3 AM), and paste the CRON URL into the command field, often prefixed with `wget -q -O /dev/null`.

#### **3. Margin (%)**

- **What this setting does:** This allows you to add a percentage margin to the fetched exchange rates. For example, if the official rate is 1 EUR = 1.10 USD, and you set a 2% margin, the module will use 1 EUR = 1.078 USD (1.10 \* 0.98) or 1 EUR = 1.122 USD (1.10 \* 1.02) depending on how the module applies the margin (usually to protect against fluctuations, so it might slightly increase the foreign currency price).
- **Effect of changing this setting:**
  - *When set to 0:* Exchange rates will be updated exactly as provided by the Bank of Finland.
  - *When set to a positive value (e.g., 2):* The module will adjust the exchange rate by this percentage. This can help cover transaction fees, currency conversion costs, or simply provide a small buffer against unfavorable rate movements, ensuring your profit margins are maintained.
- **Recommended value:** Start with 0. If you experience issues with profitability due to currency fluctuations or conversion fees, consider a small margin like 1-3%.
- **Merchant scenario / example:** If you sell a product for 100 EUR and the exchange rate is 1 EUR = 1.10 USD, the product would be 110 USD. If you set a 2% margin, the module might calculate the rate as 1 EUR = 1.078 USD, making the product 107.80 USD. This gives you a small buffer.

#### **4. Last update**

- **What this setting does:** This displays the date and time when the exchange rates were last successfully updated by the module.
- **Effect of changing this setting:** This is an informational field and cannot be changed directly. It serves as a verification that your CRON job is working correctly and the module is actively updating rates.
- **Recommended value:** This should show a recent date and time, ideally within the last 24 hours if your CRON job runs daily.
- **Merchant scenario / example:** If you set your CRON job to run daily at 3 AM, you should see the “Last update” timestamp change to reflect the current day’s 3 AM (or shortly after) every morning. If it’s not updating, it indicates an issue with your CRON job setup.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q1: My exchange rates are not updating. What should I do?**
A1: This is almost always related to the CRON job setup.
1. **Check the “Last update” timestamp:** Go to the module configuration page. If this date is old, your CRON job isn’t running.
2. **Verify CRON job setup:** Log into your hosting control panel (e.g., cPanel, Plesk). Navigate to the “Cron Jobs” or “Scheduled Tasks” section.
\* Ensure the CRON URL you copied from the module is exactly what’s in your CRON job command.
\* Make sure the command is correctly formatted (e.g., `wget -q -O /dev/null "YOUR_CRON_URL_HERE"`).
\* Confirm the frequency is set as desired (e.g., daily).
\* Check the email address associated with the CRON job (if any) for error messages.
3. **Manually run the CRON URL:** Copy the CRON URL from the module configuration and paste it directly into your web browser’s address bar. This should trigger an update. If it works, the issue is definitely with your server’s CRON job configuration. If it doesn’t work, there might be a server-side issue preventing the module from fetching data (e.g., firewall, cURL not enabled).

**Q2: My prices in foreign currencies seem slightly off, even after updates.**
A2: Check the “Margin (%)” setting in the module configuration. If you have a margin set (e.g., 2%), the module will intentionally adjust the exchange rate by that percentage. If you want exact official rates, set the margin to 0. Also, ensure your base currency in PrestaShop (Localization > Currencies) is correctly set to EUR if you are primarily dealing with Bank of Finland rates.

**Q3: Does this module work with all currencies?**
A3: The module fetches official reference data from the Bank of Finland, which primarily provides rates against the Euro. However, it intelligently calculates cross-rates for non-euro currencies. This means if the Bank of Finland provides EUR to USD and EUR to GBP, the module can derive the USD to GBP rate. As long as the Bank of Finland provides a rate for a currency against the Euro, the module should be able to update it.

**Q4: Do I need to clear my Smarty cache after updates?**
A4: No, typically not. This module updates database values (exchange rates). PrestaShop’s Smarty cache primarily affects template compilation and static content. Exchange rate changes are dynamic and should reflect immediately in your store’s pricing without needing to clear the cache.

**Q5: My custom theme is not showing the updated prices correctly.**
A5: The module updates the underlying exchange rates in PrestaShop’s database. Your theme’s currency selector and price display logic should automatically pick up these updated rates. If not, it’s likely a theme-specific issue rather than a module issue.
1. **Verify PrestaShop’s internal rates:** Go to **Localization > Currencies** in your Back Office. Check the “Exchange rate” column for your non-EUR currencies. If these rates are updated correctly, the module is working.
2. **Contact your theme developer:** If the rates are correct in the Back Office but not on the front-end, your theme might have custom caching or a specific way of handling currency display that needs attention from the theme developer.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

This section is strictly for developers, store webmasters, and technical agencies maintaining or extending the store.

### 4.1 Architecture Overview

The “Bank of Finland - currency exchange rates” module (`sprates`) is a lightweight PrestaShop module designed for a single, critical task: automating currency exchange rate updates. It leverages a front-office controller to expose a CRON-callable endpoint, which, when accessed, fetches XML data from the Bank of Finland, parses it, and updates the `ps_currency` table. The module follows a standard PrestaShop MVC pattern for its configuration and front-end trigger.

### 4.2 Controllers (`controllers/`)

#### Front-Office Controllers

- `sprates/controllers/front/cronjob.php`
  - **Class name & parent class:** `SpratesCronjobModuleFrontController` extending `ModuleFrontController`.
  - **Responsibility:** This is the core controller for the automated update process. It responds to requests made to the CRON URL. Upon execution, it:
    1. Fetches XML data from the Bank of Finland’s official exchange rate feed.
    2. Parses the XML to extract EUR-based exchange rates.
    3. Calculates cross-rates for non-EUR currencies if necessary.
    4. Applies the configured margin.
    5. Updates the `exchange_rate` column in the `ps_currency` table for all active currencies in PrestaShop.
    6. Updates the `last_update` timestamp in the module’s configuration.
    7. Outputs a simple success or error message (often suppressed by `wget -q -O /dev/null`).
- `sprates/controllers/front/index.php`
  - **Class name & parent class:** `SpratesIndexModuleFrontController` extending `ModuleFrontController`.
  - **Responsibility:** This is a placeholder controller, typically used to prevent directory listing or provide a default action if the main module dispatch isn’t used. In this module’s context, it likely serves as a fallback or a standard PrestaShop practice for modules with front controllers, but the primary logic resides in `cronjob.php`.

#### Back-Office Admin Controllers

This module does not utilize any dedicated custom Admin Controllers. All configuration is handled via the main module’s `getContent()` method.

### 4.7 Database Schema & Hooks Map

#### Database Tables

The module does not create any custom database tables. It interacts with existing PrestaShop tables:

- `ps_currency`: Updates the `exchange_rate` column for active currencies.
- `ps_configuration`: Stores module-specific settings such as `SP_RATES_MARGIN` (for the margin percentage) and `SP_RATES_LAST_UPDATE` (for the timestamp of the last update).

This module does not register any traditional display hooks (e.g., `displayHeader`, `displayFooter`) as it has no front-office visual components. Its primary “hook” mechanism is the CRON job, which triggers its front controller.
