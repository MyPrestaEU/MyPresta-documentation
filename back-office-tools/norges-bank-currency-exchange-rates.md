# Norges Bank - currency exchange rates

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for fetching external data. Your hosting environment must also support CRON jobs for automated updates.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, clicking “Configure” will take you to the main settings page for the “Norges Bank - currency exchange rates” module. This is where you control how and when your currency rates are updated.

#### **Settings & Options**

1. **CRON URL for automatic updates:**

   - **What this setting does:** This is a unique web address (URL) that, when visited, triggers the module to fetch the latest exchange rates from Norges Bank and update them in your PrestaShop store.
   - **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module. You need this URL to set up an automated task (a “CRON job”) on your web hosting server.
   - **Recommended value:** Copy this URL exactly as it appears.
   - **Merchant scenario / example:** You will provide this URL to your hosting provider or use it in your hosting control panel (like cPanel or Plesk) to schedule a task that visits this URL regularly (e.g., once a day). This ensures your rates are always fresh without you doing anything manually.
2. **Exchange Rate Margin (%):**

   - **What this setting does:** This allows you to add a percentage margin to the exchange rates fetched from Norges Bank. For example, if the official rate is 1 EUR = 10 NOK, and you set a 2% margin, your store might use 1 EUR = 9.8 NOK (or 10.2 NOK, depending on the calculation direction, typically making the foreign currency slightly more expensive for the customer to cover conversion costs).
   - **Effect of changing this setting:**
     - *When set to 0:* Your store uses the exact official exchange rates provided by Norges Bank.
     - *When set to a positive value (e.g., 2):* The module adjusts the exchange rates to include this percentage, effectively giving you a small buffer or profit margin on currency conversions. This can help cover transaction fees or simply increase your profitability.
   - **Recommended value:** Start with `0` if you want exact rates. If you need to cover costs or add a small profit, a value between `0.5` and `2` percent is common.
   - **Merchant scenario / example:** If your payment gateway charges a 1% fee for international transactions, setting a 1% margin here can help you absorb that cost without impacting your product pricing in your base currency.
3. **Last Update:**

   - **What this setting does:** This displays the date and time when the module last successfully updated the exchange rates in your store.
   - **Effect of changing this setting:** This is an informational field and cannot be changed. It helps you verify that your CRON job is working correctly and that your rates are being updated regularly.
   - **Recommended value:** Check this field periodically to ensure the updates are happening as expected.
   - **Merchant scenario / example:** After setting up your CRON job, you can check this field the next day to confirm that the module successfully ran and updated the rates.

#### **Manual Update Button**

- **What this button does:** This button allows you to manually trigger an immediate update of all exchange rates from Norges Bank.
- **Effect of clicking this button:** The module will instantly fetch the latest rates and apply them to your store. This is useful for testing or if you need an immediate update outside of your scheduled CRON job.
- **Recommended usage:** Use this for initial testing after configuration, or if there’s a significant, sudden currency fluctuation you want to reflect immediately.

#### **CRON Job Setup Instructions**

Below the settings, you will find clear instructions on how to set up the CRON job on your server. This is crucial for the module’s “maintenance-free” operation.

- **What this section does:** Provides the exact command or method you need to use with your hosting provider’s CRON job scheduler.
- **Effect of following these instructions:** Once set up, your server will automatically visit the CRON URL at specified intervals (e.g., once a day), ensuring your exchange rates are always current without manual intervention.
- **Recommended frequency:** Daily updates are usually sufficient. For highly volatile currencies or high-volume international sales, you might consider twice daily.
- **Merchant scenario / example:** In cPanel, you would go to “Cron Jobs,” select a common setting like “Once a day,” and paste the provided command into the “Command” field.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My exchange rates are not updating automatically. What should I do?**
A: This is almost always related to the CRON job setup on your server.
1. **Verify CRON Job:** Double-check your hosting control panel (cPanel, Plesk, etc.) to ensure the CRON job is correctly configured with the exact URL provided by the module and that it’s scheduled to run.
2. **CRON Path:** Sometimes the PHP path in the CRON command needs to be absolute (e.g., `/usr/bin/php` instead of just `php`). Your hosting provider can confirm this.
3. **Check “Last Update”:** If the “Last Update” field in the module configuration never changes, it confirms the CRON job isn’t executing the module’s update script.
4. **Manual Update:** Try clicking the “Manual Update” button in the module configuration. If this works, it confirms the module itself can fetch rates, pointing definitively to a CRON job issue.

**Q: The exchange rates seem incorrect or haven’t changed much.**
A:
1. **Check Norges Bank:** Compare the rates in your store with the official rates published by Norges Bank (their website is usually accessible via a quick search).
2. **Margin Setting:** Remember that your “Exchange Rate Margin (%)” setting will slightly adjust the rates. Ensure this is set as intended.
3. **Last Update:** Check the “Last Update” field. If it’s old, your CRON job isn’t running.

**Q: Does this module affect my default currency?**
A: No, the module only updates the exchange rates for non-default currencies relative to your default currency. Your default currency’s value remains unchanged.

**Q: I’ve updated my theme, and now the currency selector isn’t working correctly.**
A: This module only updates the *values* of the exchange rates. The visual display and functionality of the currency selector itself are handled by PrestaShop’s core or your theme. If the selector isn’t working, it’s likely a theme or core PrestaShop issue, not directly related to this module. Clear your Smarty cache (**Advanced Parameters > Performance**) and check your theme’s configuration.

**Q: Can I use this module with other currency modules?**
A: It’s generally not recommended to run multiple modules that try to update exchange rates, as they might conflict or overwrite each other’s data. This module is designed to be a standalone solution for Norges Bank rates. If you need rates from a different source, you should disable this module and use the other one.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

### 4.1 Architecture Overview

The “Norges Bank - currency exchange rates” module (`nbrates`) is a lightweight PrestaShop module primarily focused on a single, critical task: fetching and updating currency exchange rates. It leverages PrestaShop’s `Module` class for installation and configuration and uses a front controller to expose a CRON endpoint for automated updates. The core logic involves making an HTTP request to the Norges Bank API, parsing the XML response, calculating cross-rates, and updating PrestaShop’s `ps_currency` table.

### 4.2 Controllers (`controllers/`)

- **Front-Office Controllers**:

  - `controllers/front/cronjob.php`

When accessed via its URL (provided in the module configuration), it triggers the `cronjob()` method within the main `nbrates` module class. It’s designed to be called by an external scheduler (CRON) and outputs a simple success/failure message. It does not render any visual content for the user.
