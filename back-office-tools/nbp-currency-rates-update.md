# NBP currency rates update

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.5.x, 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions like cURL, JSON, and OpenSSL are typically required and are standard on most modern web hosting environments. Your hosting must also support setting up cron jobs.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, click “Configure” next to the “NBP currency rates update” module. You will be presented with the main configuration screen.

#### **Cron Job URL**

- **What this setting does:** This displays a unique URL that you will use to set up an automated task (a “cron job”) on your web server. When this URL is accessed, the module will connect to the NBP servers, fetch the latest currency rates, and update them in your PrestaShop store.
- **Effect of changing this setting:** You cannot change this URL directly. It is generated by the module.
- **Recommended value:** Copy this URL exactly as it appears.
- **Merchant scenario / example:** You will take this URL and paste it into your hosting control panel’s “Cron Jobs” section (e.g., cPanel, Plesk, or a custom server cron configuration). This tells your server to visit this URL at specified intervals (e.g., every day at 3 AM), triggering the currency update process automatically.

#### **Cron Job Frequency**

- **What this setting does:** This is not a setting you change *within* PrestaShop, but rather a recommendation for how often you should set up your server’s cron job to call the URL.
- **Effect of changing this setting:** This text simply advises you. The actual frequency is controlled by your server’s cron job setup.
- **Recommended value:** “Once a day” is generally sufficient for most stores, as NBP rates typically update daily.
- **Merchant scenario / example:** If you set your server’s cron job to run daily, your store’s currency rates will be refreshed once every 24 hours, ensuring they are always up-to-date with NBP data. Running it more frequently (e.g., hourly) is usually unnecessary and might put undue load on your server or the NBP API.

#### **Important Note on Cron Jobs**

- **What this setting does:** This section provides crucial instructions on how to set up the cron job on your server. It explains that you need to access your hosting control panel (like cPanel or Plesk) and add a new cron job.
- **Effect of changing this setting:** This is an informational text. You need to follow these instructions outside of PrestaShop.
- **Recommended value:** Read this carefully and follow the steps provided by your hosting provider for setting up cron jobs.
- **Merchant scenario / example:** Your hosting provider will have a section, usually called “Cron Jobs” or “Scheduled Tasks,” where you can add a new command. You’ll typically choose a frequency (e.g., “Once a day”), and then paste the “Cron Job URL” into the command field, often prefixed with `wget -q -O /dev/null`. If you’re unsure, contact your hosting provider’s support.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My currency rates are not updating, even after I set up the cron job. What should I do?**
A:

1. **Check the Cron Job URL:** Make sure you copied the URL exactly from the module configuration page and pasted it correctly into your hosting control panel’s cron job settings.
2. **Verify Cron Job Execution:** Check your hosting provider’s cron job logs (if available) to see if the cron job is actually running at the scheduled time. Sometimes, the command might be incorrect, or the path to `wget` might need adjustment.
3. **Test Manually:** Try visiting the “Cron Job URL” directly in your web browser. This should trigger an immediate update. If rates update after a manual visit, the issue is with your server’s cron job setup, not the module itself.
4. **Check PrestaShop Currencies:** Ensure the currencies you want to update are enabled in PrestaShop (**International > Currencies**) and that they have a valid ISO code that NBP can recognize (e.g., USD, EUR, GBP).
5. **Clear Cache:** Sometimes, PrestaShop’s cache might prevent you from seeing immediate changes. Go to **Advanced Parameters > Performance** and click “Clear cache”.

**Q: Does this module update all currencies in my store?**
A: It updates currencies for which NBP provides exchange rates, relative to PLN. The module is smart enough to convert these rates to your store’s default currency. For example, if your default currency is EUR, and NBP provides USD/PLN and EUR/PLN, the module can calculate USD/EUR. If NBP does not provide a rate for a specific currency, that currency’s rate will not be updated by this module.

**Q: Can I set the update frequency to be more often than once a day?**
A: While you can configure your server’s cron job to run more frequently (e.g., every hour), NBP exchange rates typically update once a day. Running the cron job more often than daily is usually unnecessary and won’t provide fresher data, but it won’t harm anything either.

**Q: I’m getting an error message when I try to configure the module or when the cron job runs.**
A:

1. **Check PHP Version:** Ensure your PHP version is within the supported range (PHP 5.6 - 8.5).
2. **Server Connectivity:** The module needs to connect to the NBP website to fetch rates. Ensure your server has outbound internet access and is not blocked by a firewall from accessing external URLs.
3. **PrestaShop Debug Mode:** Enable PrestaShop’s debug mode (**Advanced Parameters > Performance > Debug mode**) to see more detailed error messages, which can help pinpoint the problem. Remember to disable it after troubleshooting.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

This section is strictly for developers, store webmasters, and technical agencies maintaining or extending the store.

### 4.1 Architecture Overview

The `NBP currency rates update` module is a lightweight PrestaShop module primarily designed to perform a single, critical task: fetching and updating currency exchange rates from the National Bank of Poland (NBP) via a scheduled cron job. It follows a standard PrestaShop module structure, leveraging `ModuleFrontController` for its cron endpoint and the main module class for configuration and installation. The core logic resides within the `cronjob.php` file, which acts as both the main module class and the entry point for the cron execution.

### 4.2 Controllers (`controllers/`)

- **Front-Office Controllers**:

  - `nbprates/controllers/front/cronjob.php`
    - **Class name & parent class**: `NbpratesCronjobModuleFrontController` extends `ModuleFrontController`
    - **Responsibility**: This controller serves as the public endpoint for the cron job. When accessed via the unique URL generated by the module, it triggers the currency update logic. It does not render any visual output but executes the rate fetching and updating process. It’s designed to be called by `wget` or `curl` from a server’s cron scheduler.
  - `nbprates/controllers/front/index.php`
    - **Class name & parent class**: `NbpratesIndexModuleFrontController` extends `ModuleFrontController`
    - **Responsibility**: This is a placeholder controller, often included in modules to prevent directory listing if `index.php` is not present in the `controllers/front` directory. It typically does nothing more than redirect to the home page or display a “404 Not Found” error. It does not contain any specific business logic for this module.
- **Back-Office Admin Controllers**:

  - None. All configuration is handled directly within the main module’s `getContent()` method.

### 4.3 Core Classes & Models (`classes/`)

- None. The module’s logic is primarily contained within the main module file (`nbprates/cronjob.php`).

### 4.4 JavaScript Assets (`views/js/`)

- None. The module does not use any custom JavaScript.

### 4.5 CSS Stylesheets (`views/css/`)

- None. The module does not use any custom CSS.

### 4.6 Smarty Template Structure (`views/templates/`)

- **Admin templates (`views/templates/admin/`)**:
  - `nbprates/views/admin.tpl`
    - **Purpose**: This template is rendered by the `getContent()` method of the main module class (`NbpratesCronjob`) to display the module’s configuration form in the PrestaShop Back Office.
    - **Content**: It typically displays the “Cron Job URL” and instructions for setting up the cron job. It’s a static display of information rather than an interactive form with input fields.

### 4.7 Database Schema & Hooks Map

- **Database Tables**:

  - The module does not create any custom SQL tables.
  - It stores its configuration (specifically the generated cron token) in the `ps_configuration` table. The key for the cron token would typically be `NBP_CRON_TOKEN`.
  - It updates existing currency exchange rates in the `ps_currency` table (specifically the `conversion_rate` column).
- **Registered Hooks Table**:
  The module does not explicitly register to any standard PrestaShop display hooks (like `displayHeader`, `displayFooter`, etc.) for front-office rendering. Its primary “hook” is the `ModuleFrontController` endpoint which is called externally by the server’s cron job.

| Hook Name | Execution Timing | Technical Purpose |
| --- | --- | --- |
| `install()` | During module installation | Creates the unique cron token and stores it in `ps_configuration`. |
| `uninstall()` | During module uninstallation | Deletes the cron token from `ps_configuration`. |
| `actionFrontControllerSetMedia` | Not explicitly registered, but `ModuleFrontController` implicitly handles asset loading if any were present. | N/A (no assets are loaded by this module). |
