# NBU Currency Exchange & Rates

## 1. Requirements & Compatibility
- **Supported PrestaShop Versions**: PrestaShop 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are required for fetching data from external APIs. Most modern hosting environments meet these requirements by default.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)
After installation, click "Configure" to access the module's settings. This is where you'll define how the NBU rates are applied to your store.

**Screen Name:** NBU Currency Exchange & Rates Configuration

**Settings & Options:**

1.  **CRON Job URL:**
    -   **What this setting does:** This displays the unique URL that your server's CRON scheduler needs to call periodically. When this URL is accessed, the module automatically fetches the latest NBU exchange rates and updates them in your PrestaShop store.
    -   **Effect of changing this setting:** You cannot change this URL directly. It's generated by the module. If you don't set up a CRON job to call this URL, the exchange rates will not update automatically, and you'll have to manually trigger updates (if such an option exists, which it doesn't for this module's primary function).
    -   **Recommended value:** Copy this URL and set it up in your hosting control panel's CRON job scheduler.
    -   **Merchant scenario / example:** You copy `https://yourstore.com/module/nburates/cronjob?token=YOUR_SECURE_TOKEN` and add it to your cPanel or Plesk CRON jobs to run once a day (e.g., at 3 AM). This ensures your UAH prices are always up-to-date before your customers start shopping.

2.  **CRON Job Frequency:**
    -   **What this setting does:** This is a recommendation for how often you should run the CRON job. The NBU typically updates rates once a day.
    -   **Effect of changing this setting:** This is purely informational. Changing your actual CRON job frequency (in your hosting panel) will affect how often rates are updated. Running it too frequently (e.g., every minute) is unnecessary and can consume server resources without benefit, as NBU rates don't change that often. Running it too infrequently (e.g., once a week) means your rates might be outdated.
    -   **Recommended value:** Once a day.
    -   **Merchant scenario / example:** You set your server's CRON job to run `0 3 * * *` (every day at 3 AM) to match the NBU's daily updates.

3.  **Currency to Update (UAH):**
    -   **What this setting does:** This field allows you to specify the ID of the Ukrainian Hryvnia (UAH) currency in your PrestaShop store. The module needs to know which currency to target for updates.
    -   **Effect of changing this setting:** If the ID is incorrect or left empty, the module won't be able to find and update the UAH currency, and your prices will not reflect the NBU rates.
    -   **Recommended value:** The ID of your UAH currency. You can find this by navigating to **International > Currencies** in your PrestaShop Back Office, editing the UAH currency, and looking at the URL (e.g., `id_currency=3` means the ID is 3).
    -   **Merchant scenario / example:** Your UAH currency has an ID of `3`. You enter `3` into this field. Now, when the CRON job runs, the module knows to update the exchange rate for the currency with ID `3`.

4.  **Margin (%):**
    -   **What this setting does:** This allows you to add a percentage margin (markup or markdown) to the fetched NBU exchange rates. A positive value increases the rate (making UAH prices higher), and a negative value decreases it (making UAH prices lower).
    -   **Effect of changing this setting:**
        -   *When set to 0:* The module uses the exact NBU rate.
        -   *When set to 2:* The UAH exchange rate will be 2% higher than the official NBU rate. For example, if NBU says 1 EUR = 40 UAH, with a 2% margin, your store will use 1 EUR = 40.8 UAH. This can help cover transaction fees or provide a slight profit buffer.
        -   *When set to -1:* The UAH exchange rate will be 1% lower than the official NBU rate. This might be used for promotional pricing or to offer a slight discount.
    -   **Recommended value:** Depends on your business strategy. `0` for exact NBU rates, or a small positive percentage (e.g., `1` or `2`) to cover costs.
    -   **Merchant scenario / example:** You want to slightly offset payment gateway fees for UAH transactions. You set the margin to `1.5`. Now, all UAH prices will be calculated using the NBU rate plus an additional 1.5%.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q1: My UAH prices are not updating. What should I do?**
A1:
*   **Check CRON Job:** The most common reason is an incorrectly set up or missing CRON job. Verify that the CRON job URL from the module configuration is correctly added to your hosting panel and is scheduled to run.
*   **Check UAH Currency ID:** Ensure the "Currency to Update (UAH)" setting in the module configuration matches the exact ID of your UAH currency in PrestaShop (**International > Currencies**).
*   **Check NBU Availability:** Occasionally, the NBU API might be temporarily unavailable. Wait a few hours and check again. The module is designed to use the last known rate if the API is down.
*   **Server Logs:** Check your server's CRON job logs (if available) for any errors when the CRON URL is called.

**Q2: The module is installed, but I don't see any visual changes in my store.**
A2: This module works in the background to update currency rates. It doesn't add new blocks or visual elements to your store. Its effect is seen in the accurate calculation of product prices when UAH is the selected currency.

**Q3: Can I manually update the rates if the CRON job fails?**
A3: The module's primary mechanism is the CRON job. While you can manually update currency rates in PrestaShop (**International > Currencies**), doing so would override the NBU rates. The best practice is to ensure your CRON job is working correctly. If you need an immediate update, you can manually trigger the CRON URL once by visiting it in your browser (though this is not the intended long-term solution).

**Q4: What happens on bank holidays when NBU doesn't publish new rates?**
A4: The module is designed to handle this intelligently. If the NBU does not publish new rates on a given day (e.g., weekends or public holidays), the module will typically retain the last successfully fetched rate. This ensures your UAH prices remain stable and consistent.

**Q5: How do I clear the Smarty cache if I make changes and don't see them?**
A5: While this module's changes are primarily data-driven (currency rates) and less about visual templates, clearing the cache can sometimes help. Go to **Advanced Parameters > Performance** in your PrestaShop Back Office. Set "Template compilation" to "Recompile templates if the files have been updated" or "Force compilation" and click "Clear cache." Remember to revert to "Never recompile template files" for production performance after troubleshooting.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)
This section provides a detailed technical overview for developers and webmasters.

### 4.1 Architecture Overview
The `NBU Currency Exchange & Rates` module is a lightweight PrestaShop module designed to integrate external currency exchange rates from the National Bank of Ukraine (NBU) API. It follows a simple MVC-like pattern within the PrestaShop module structure. The core logic resides in the main module file (`cronjob.php`), which handles configuration, installation, and the primary CRON job execution. It utilizes PrestaShop's `Configuration` class for storing settings and `Currency` ObjectModel for updating rates. The module's main functionality is exposed via a front controller, specifically designed to be called by a server-side CRON job.

### 4.2 Controllers (`controllers/`)

-   **Front-Office Controllers**:
    *   `nburates/controllers/front/cronjob.php`
        *   **Class Name:** `NburatesCronjobModuleFrontController` (extends `ModuleFrontController`)
        *   **Responsibility:** This is the critical endpoint for the CRON job. When accessed, it performs the following actions:
            1.  Validates a secure token (`token`) passed in the URL to prevent unauthorized access.
            2.  Retrieves module configuration settings (UAH currency ID, margin).
            3.  Fetches the latest NBU exchange rates from the official NBU API (likely `https://bank.gov.ua/NBUStatService/v1/statdirectory/exchangenew?json`).
            4.  Parses the JSON response to extract relevant currency rates.
            5.  Applies the configured margin to the fetched rates.
            6.  Updates the exchange rate for the specified UAH currency in the `ps_currency` table using PrestaShop's `Currency` ObjectModel.
            7.  Handles error conditions (e.g., API unreachable, invalid response) by logging or falling back to previous rates.
            8.  Outputs a simple success or error message, suitable for CRON job logging.
    *   `nburates/controllers/front/index.php`
        *   **Class Name:** `NburatesIndexModuleFrontController` (extends `ModuleFrontController`)
        *   **Responsibility:** This is a standard empty `index.php` front controller, often included in modules to prevent directory listing or to serve as a placeholder. It typically doesn't contain specific logic for this module's core function.

-   **Back-Office Admin Controllers**:
    *   None. All configuration is handled directly within the `getContent()` method of the main module file.

### 4.3 Core Classes & Models (`classes/`)
-   None. The module directly interacts with PrestaShop's core `Currency` ObjectModel and `Configuration` class.

### 4.4 JavaScript Assets (`views/js/`)
-   None. The module does not use any custom JavaScript.

### 4.5 CSS Stylesheets (`views/css/`)
-   None. The module does not use any custom CSS. The admin configuration page relies on PrestaShop's default Back Office styling.

### 4.6 Smarty Template Structure (`views/templates/`)

-   **Admin templates (`views/templates/admin/`)**:
    *   `nburates/views/admin.tpl`
        *   **Purpose:** This template renders the module's configuration form in the PrestaShop Back Office.
        *   **Content:** It displays the CRON job URL, CRON frequency recommendation, input fields for the UAH currency ID, and the margin percentage. It typically uses standard PrestaShop form helpers and styling.

### 4.7 Database Schema & Hooks Map

-   **Database Tables**:
    *   The module does not create any custom database tables.
    *   It interacts with the `ps_configuration` table to store its settings (e.g., `NBU_RATES_UAH_CURRENCY_ID`, `NBU_RATES_MARGIN`, `NBU_RATES_SECURE_TOKEN`).
    *   It updates the `ps_currency` table, specifically the `conversion_rate` column for the UAH currency.

-   **Registered Hooks Table**:
    The module does not register any traditional display hooks (`displayHeader`, `displayFooter`, etc.) that render content in the front office. Its primary "hook" is the `action` it performs when its front controller is called by the CRON job.

| Hook Name | Execution Timing | Technical Purpose |
|---|---|---|
| `actionModuleInstall` | During module installation | Creates configuration entries, generates secure token. |
| `actionModuleUninstall` | During module uninstallation | Cleans up configuration entries. |
| (Implicit) `ModuleFrontController::initContent()` for `NburatesCronjobModuleFrontController` | When the CRON URL is accessed | Fetches NBU rates, applies margin, updates UAH currency rate. |
