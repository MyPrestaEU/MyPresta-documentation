# Custom Order Reference Generator Pro

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 7.1 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL).

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure > Custom Order Reference Generator Pro)

This is the main configuration screen where you define your custom order reference patterns and rules. The page is typically organized into several tabs or sections for clarity.

#### **General Settings Tab**

This tab controls the fundamental behavior of the module.

- **Enable Custom Order Reference Generation:**

  - **What this setting does:** This is the master switch for the module. When enabled, the module will take over the generation of order references. When disabled, PrestaShop will revert to its default order reference generation method.
  - **Effect of changing this setting:**
    - *When enabled:* All new orders will receive a reference generated by this module according to your defined rules.
    - *When disabled:* All new orders will use PrestaShop’s default reference format. Existing orders will retain their references.
  - **Recommended value:** YES (to activate the module’s functionality).
  - **Merchant scenario / example:** If you want to start using custom references, enable this. If you need to temporarily revert to PrestaShop’s default for troubleshooting, disable it.
- **Default Reference Pattern:**

  - **What this setting does:** This defines the basic structure for your custom order references. You can combine static text with dynamic “shortcodes” that pull information from the order, customer, or date.
  - **Effect of changing this setting:** This directly dictates the format of your order references when no specific rule applies.
  - **Recommended value:** Start with something simple like `MYSTORE-{DATE:YMD}-{ID_ORDER}` or `ORD-{RAND:6}`.
  - **Merchant scenario / example:**
    - `MYSTORE-{DATE:YMD}-{ID_ORDER}`: Generates references like `MYSTORE-20231027-12345`. This is great for easily identifying orders from your store and seeing the date they were placed, along with a sequential order ID.
    - `ORD-{RAND:6}`: Generates references like `ORD-A1B2C3`. This provides a short, random, and unique reference.
    - `{CUSTOMER_LASTNAME}-{ID_ORDER}`: Generates references like `SMITH-12345`. Useful for B2B or personalized service.
  - **Available Shortcodes:**
    - `{ID_ORDER}`: The unique ID of the order (sequential).
    - `{ID_CUSTOMER}`: The unique ID of the customer.
    - `{DATE:format}`: Current date and time. `format` uses PHP’s `date()` function syntax (e.g., `YMD` for 20231027, `His` for 143059).
    - `{RAND:length}`: A random string of alphanumeric characters, `length` specifies how many characters (e.g., `RAND:6`).
    - `{CUSTOMER_FIRSTNAME}`: Customer’s first name.
    - `{CUSTOMER_LASTNAME}`: Customer’s last name.
    - `{CUSTOMER_EMAIL}`: Customer’s email address.
    - `{PAYMENT_METHOD}`: The payment method used for the order.
    - `{DELIVERY_COUNTRY_ISO}`: ISO code of the delivery country (e.g., US, FR).
    - `{DELIVERY_CITY}`: City of the delivery address.
    - `{CART_TOTAL}`: Total value of the cart.
    - `{PRODUCT_SKU}`: SKU of the first product in the cart (use with caution, can be long).
    - `{PRODUCT_NAME}`: Name of the first product in the cart (use with caution).
    - `{SHOP_NAME}`: Your PrestaShop store’s name.
- **Sequential Counter Start Value:**

  - **What this setting does:** If your reference pattern includes `{ID_ORDER}` or a similar sequential element, this defines the starting number for that sequence.
  - **Effect of changing this setting:** New orders will start their sequential numbering from this value. This is useful if you’re migrating from another system or want to restart numbering.
  - **Recommended value:** 1 (for a fresh start) or a higher number if you need to continue a sequence.
  - **Merchant scenario / example:** If you previously had 1000 orders and want your new custom references to start from 1001, set this to 1001.
- **Reference Length Limit:**

  - **What this setting does:** PrestaShop has a default limit for order reference length. This allows you to define a maximum length for your generated references. If a reference exceeds this, it will be truncated.
  - **Effect of changing this setting:** Ensures your references fit within database constraints and display correctly in all areas of PrestaShop.
  - **Recommended value:** 9 (PrestaShop’s default is often 9, but you can increase it if your theme/database supports it, up to 32 characters is generally safe).
  - **Merchant scenario / example:** If your pattern `MYSTORE-{DATE:YMD}-{ID_ORDER}` results in `MYSTORE-20231027-12345` (21 characters), and you set the limit to 9, it might become `MYSTORE-2`. Be mindful of truncation.
- **Preview Reference:**

  - **What this setting does:** This is a utility field that allows you to test your `Default Reference Pattern` with a dummy order ID to see what the generated reference would look like.
  - **Effect of changing this setting:** No direct effect on your store, purely a testing tool.
  - **Recommended value:** Use it frequently when designing your patterns.
  - **Merchant scenario / example:** Enter `12345` as a dummy order ID and click “Generate Preview” to see how `MYSTORE-{DATE:YMD}-{ID_ORDER}` would look.

#### **Rules Tab**

This tab is where you define specific conditions under which different order reference patterns should be applied, overriding the default pattern. Rules are processed from top to bottom, and the first matching rule is applied.

- **Add New Rule / Edit Rule:**

  - **What this does:** Allows you to create a new rule or modify an existing one. Each rule consists of:
    - **Rule Name:** A descriptive name for your internal reference (e.g., “High Value Orders”, “French Customers”).
    - **Rule Pattern:** The custom reference pattern to use if this rule matches (same shortcodes as the default pattern).
    - **Conditions:** One or more criteria that must be met for this rule to apply.
  - **Effect of changing this setting:** Adds or modifies a conditional reference pattern.
  - **Recommended value:** Create rules for your most important business segments.
  - **Merchant scenario / example:**
    - **Rule 1: High Value Orders**
      - **Pattern:** `VIP-{ID_ORDER}-{DATE:YMD}`
      - **Condition:** `Cart Total` is `greater than` `500`
      - **Effect:** Any order over €500 will get a reference like `VIP-12345-20231027`.
    - **Rule 2: French Customers**
      - **Pattern:** `FR-{ID_ORDER}`
      - **Condition:** `Delivery Country` is `France`
      - **Effect:** Orders shipping to France will get `FR-12345`.
    - **Rule 3: Specific Product Orders**
      - **Pattern:** `PROD-XYZ-{ID_ORDER}`
      - **Condition:** `Product in Cart` is `Product Name XYZ`
      - **Effect:** Orders containing “Product Name XYZ” will get `PROD-XYZ-12345`.
- **Rule Conditions (for each rule):**

  - **What this does:** Defines the criteria for a rule to be active. You can combine multiple conditions using “AND” logic.
  - **Available Conditions:**
    - **Cart Total:** Based on the total value of the order.
    - **Customer Group:** Based on the group the customer belongs to (e.g., Visitors, Customers, Guests, or custom groups).
    - **Delivery Country:** Based on the country of the shipping address.
    - **Payment Method:** Based on the payment module used (e.g., Bank Wire, PayPal).
    - **Product in Cart:** Based on whether a specific product (by ID or name) is present in the order.
    - **Carrier:** Based on the chosen shipping carrier.
  - **Effect of changing this setting:** Determines when a specific custom reference pattern is used.
  - **Recommended value:** Use conditions that clearly segment your orders.
  - **Merchant scenario / example:** A rule for “Wholesale Customers” might use `Customer Group is Wholesale`. A rule for “Express Shipping” might use `Carrier is DHL Express`.

#### **Advanced Settings Tab**

This tab contains settings for more technical aspects and maintenance.

- **JSON Backup / Restore:**

  - **What this does:** Allows you to export your module’s configuration (patterns, rules) to a JSON file or import a previously saved configuration.
  - **Effect of changing this setting:**
    - *Backup:* Creates a downloadable file of your settings.
    - *Restore:* Overwrites current settings with those from the uploaded JSON file.
  - **Recommended value:** Always back up your configuration before making major changes or upgrading your PrestaShop store.
  - **Merchant scenario / example:** Before updating PrestaShop or moving your store to a new server, download a backup of your custom reference rules. If you make a mistake with a rule, you can easily restore a previous version.
- **Reset Module Configuration:**

  - **What this does:** Deletes all custom patterns and rules, reverting the module to its default, freshly installed state.
  - **Effect of changing this setting:** All your custom reference patterns and rules will be lost.
  - **Recommended value:** Use with extreme caution, only if you want to completely start over.
  - **Merchant scenario / example:** If your rules have become too complex or are causing issues, and you want to start from scratch, you can use this. Always back up first!

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q1: My custom references aren’t showing up, or I’m still seeing PrestaShop’s default references.**
A1: First, ensure the module is **enabled** in the “General Settings” tab. Also, check if you’ve cleared your PrestaShop cache (Advanced Parameters > Performance > Clear Cache). If you have specific rules, ensure their conditions are met and that the rules are correctly ordered (the first matching rule applies).

**Q2: My custom references are too long or are being cut off.**
A2: Check the “Reference Length Limit” in the “General Settings” tab. PrestaShop has a default limit (often 9 characters) for order references in its database. If your custom pattern generates longer references, you might need to increase this limit. Be cautious, as increasing it too much might cause display issues in some themes or older PrestaShop versions. It’s generally safe to go up to 32 characters. If you need longer, consult a developer.

**Q3: I made a mistake with my rules, and now my references are wrong. How do I fix it?**
A3: If you have a recent JSON backup (from the “Advanced Settings” tab), you can restore it. Otherwise, you’ll need to manually edit or delete the problematic rules. If you want to start completely fresh, use the “Reset Module Configuration” option, but be aware this will delete *all* your custom patterns and rules.

**Q4: Can I use this module with multiple stores (multistore setup)?**
A4: Yes, the module is designed to be compatible with PrestaShop’s multistore feature. You can configure different reference patterns and rules for each store from the module’s configuration page, by selecting the specific shop context in the PrestaShop back office.

**Q5: What happens to existing orders when I change the reference pattern?**
A5: Changing the reference pattern or rules only affects *new* orders placed after the change. Existing orders will retain their original order references. The module does not retroactively modify past order data.
