# Danmarks Nationalbank - currency exchange rates

## 1. Requirements & Compatibility

- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for fetching external data. These are almost always available on modern hosting environments.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, click “Configure” next to the module name to access its settings. This is where you’ll manage how exchange rates are fetched and applied.

The configuration page will display a list of all active currencies in your store, allowing you to manage the exchange rate and profit margin for each.

**For Each Currency Listed (e.g., USD, EUR, GBP):**

- **Current Exchange Rate:**

  - **What this setting does:** This field displays the current exchange rate for this currency against your store’s default currency (e.g., DKK if your store is based in Denmark). This value is automatically updated by the module when the cron job runs.
  - **Effect of changing this setting:** You can manually adjust this if needed, but the module’s primary purpose is to automate this. Any manual change will be overwritten by the next cron job run.
  - **Recommended value:** Let the module update this automatically. Only manually adjust for temporary, specific needs.
  - **Merchant scenario / example:** If the module hasn’t run yet, or if you need to quickly adjust a rate before the next scheduled update, you might manually change it. However, for long-term accuracy, rely on the automated updates.
- **Markup / Markdown (%):**

  - **What this setting does:** This allows you to add a percentage-based profit margin (markup) or discount (markdown) to the fetched exchange rate.
    - A positive value (e.g., `+2%`) will increase the exchange rate, meaning customers pay slightly more in that currency, ensuring you cover conversion fees or gain a small profit.
    - A negative value (e.g., `-1%`) will decrease the exchange rate, making the foreign currency price slightly lower.
  - **Effect of changing this setting:** This percentage is applied *after* the official rate is fetched from Danmarks Nationalbank.
    - *When set to `+2%` for USD:* If the official rate is 1 USD = 6.50 DKK, your store will use 1 USD = 6.63 DKK (6.50 \* 1.02).
    - *When set to `-1%` for EUR:* If the official rate is 1 EUR = 7.45 DKK, your store will use 1 EUR = 7.3755 DKK (7.45 \* 0.99).
  - **Recommended value:** Start with `0%` and adjust based on your business model, payment gateway fees, and desired profit margins. Many merchants add a small markup (e.g., `0.5%` to `2%`) to cover transaction costs.
  - **Merchant scenario / example:** Your payment processor charges a 1.5% fee for converting EUR to DKK. You can set a `+1.5%` markup for EUR to effectively pass this cost onto the customer and maintain your profit margin.

**Cron Job URL:**

- **What this setting does:** This displays a unique URL that you need to set up as a cron job on your server. When this URL is accessed, the module connects to Danmarks Nationalbank, fetches the latest exchange rates, applies your defined markups/markdowns, and updates them in your PrestaShop store.
- **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module.
- **Recommended value:** Copy this URL and set it up in your hosting control panel (cPanel, Plesk, etc.) or with a cron service.
- **Merchant scenario / example:** You want your exchange rates to update daily at 3 AM. You would copy this URL and configure a cron job on your server to execute it every day at 3 AM.

**Save Button:**

- **What this setting does:** Applies any changes you’ve made to the Markup/Markdown percentages.
- **Effect of changing this setting:** Your new profit margins will be saved and applied the next time the cron job runs and updates the rates.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My exchange rates are not updating. What should I do?**
A:

1. **Check Cron Job:** The most common reason is an incorrectly set up or non-running cron job. Verify with your hosting provider that the cron job URL provided in the module configuration is correctly scheduled and executing.
2. **Module Status:** Ensure the module is enabled in your PrestaShop Back Office.
3. **Server Connectivity:** Confirm your server has outbound internet access to connect to Danmarks Nationalbank’s API.
4. **Clear Cache:** Sometimes, PrestaShop’s cache might prevent immediate display of updated rates. Go to **Advanced Parameters > Performance** and click “Clear cache”.

**Q: Can I set different markups for different currencies?**
A: Yes, absolutely! That’s one of the core features of this module. On the module configuration page, you’ll find a separate “Markup / Markdown (%)” field for each active currency in your store.

**Q: What happens if Danmarks Nationalbank’s service is temporarily unavailable?**
A: The module will attempt to fetch the rates. If it fails, it will typically retain the last successfully updated rates. It’s designed to be resilient, but consistent failures might indicate a server connectivity issue on your end or a prolonged outage from the source.

**Q: Will this module affect my SEO or product URLs?**
A: No, this module only manages currency exchange rates. It does not alter product URLs, meta descriptions, or any other SEO-related elements. Its impact is purely on pricing display.

**Q: My custom theme doesn’t seem to display the updated prices correctly.**
A: This module updates the core PrestaShop exchange rates. If your theme uses standard PrestaShop functions to display prices, it should reflect the changes. If not, it might be a caching issue (clear cache as above) or a highly customized theme that bypasses standard PrestaShop price rendering. In such rare cases, you might need a web developer to investigate your theme’s price display logic.
