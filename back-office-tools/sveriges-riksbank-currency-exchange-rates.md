## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, click “Configure” to access the module’s main settings page. This is where you’ll set up how the module fetches and applies exchange rates.

#### **General Settings**

- **Enable Module:**

  - **What this setting does:** This is the master switch to activate or deactivate the module’s functionality.
  - **Effect of changing this setting:**
    - *When enabled:* The module will be active, and its cron job and rate update logic will function according to your other settings.
    - *When disabled:* The module will be inactive, and no automatic rate updates will occur. Your currency rates will remain as they were last set (either manually or by a previous module update).
  - **Recommended value:** YES
  - **Merchant scenario / example:** If you’re just setting up or troubleshooting, you might disable it temporarily. For normal operation, it should always be enabled.
- **Cron Job URL:**

  - **What this setting does:** This displays a unique URL that you need to set up as a “cron job” on your web hosting server. A cron job is a scheduled task that tells your server to visit this URL at regular intervals (e.g., once a day). When the URL is visited, the module automatically fetches and updates the currency rates.
  - **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module. The effect comes from *using* this URL in your hosting panel.
    - *When correctly set up as a cron job:* Your currency rates will automatically update at the specified frequency (e.g., daily).
    - *When not set up as a cron job:* Rates will not update automatically. You would have to manually visit this URL in your browser to trigger an update, which defeats the purpose of automation.
  - **Recommended value:** Copy this URL and set it up as a daily cron job on your server.
  - **Merchant scenario / example:** You would typically set this to run once every 24 hours to ensure your rates are always fresh. Consult your hosting provider’s documentation or support for how to set up a cron job (often found in cPanel or Plesk under “Cron Jobs” or “Scheduled Tasks”).

#### **Currency-Specific Settings**

Below the general settings, you will see a list of all active currencies in your PrestaShop store. For each currency, you can configure specific settings:

- **Currency Name (e.g., Euro, US Dollar):**

  - **What this setting does:** Identifies the currency you are configuring.
  - **Effect of changing this setting:** This is just a label; you cannot change the currency name here.
- **Markup / Markdown (%):**

  - **What this setting does:** This allows you to apply a percentage adjustment to the exchange rate fetched from Sveriges Riksbank.
    - A **positive value (markup)** increases the exchange rate, meaning you get more of the foreign currency for your base currency. This is useful for covering transaction fees or increasing your profit margin.
    - A **negative value (markdown)** decreases the exchange rate, meaning you get less of the foreign currency. This might be used for promotional purposes or if you want to offer a slightly better rate to customers.
  - **Effect of changing this setting:**
    - *When set to 0:* The exchange rate will be exactly what Sveriges Riksbank provides.
    - *When set to 2 (markup):* If the Riksbank rate is 1 EUR = 10 SEK, with a 2% markup, your store will use 1 EUR = 10.20 SEK. This means when a customer pays in EUR, you effectively receive more SEK.
    - *When set to -1 (markdown):* If the Riksbank rate is 1 EUR = 10 SEK, with a 1% markdown, your store will use 1 EUR = 9.90 SEK. This means when a customer pays in EUR, they get a slightly better rate.
  - **Recommended value:** Depends on your business strategy. A common practice is to add a small markup (e.g., 1-3%) to cover payment gateway fees and currency conversion costs.
  - **Merchant scenario / example:** If your payment processor charges a 1.5% fee for converting EUR to SEK, you might set a 2% markup for EUR to ensure you cover that fee and retain a small profit.

#### **Save Button**

- **What this button does:** Saves all the changes you’ve made on the configuration page.
- **Effect of clicking this button:** Your new settings (enable/disable, markup/markdown percentages) will be applied. The next time the cron job runs, or you manually trigger an update, these new settings will be used.
- **Recommended action:** Always click “Save” after making any changes.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q1: My currency rates aren’t updating automatically. What should I check?**
A1:

- **Is the module enabled?** Go to Modules > Module Manager > Sveriges Riksbank - currency exchange rates and ensure “Enable Module” is set to YES.
- **Is the cron job set up correctly?** Double-check your hosting control panel (cPanel, Plesk, etc.) to ensure the Cron Job URL provided in the module configuration is correctly entered and scheduled to run. Make sure the command is correct (e.g., `wget -q -O /dev/null "YOUR_CRON_URL"` or `curl -s "YOUR_CRON_URL"`).
- **Are there any errors when manually visiting the Cron Job URL?** Try pasting the Cron Job URL into your browser. If you see an error message, it might indicate a server issue or a problem with the module’s connection to Sveriges Riksbank.
- **Server connectivity:** Ensure your server can make outbound connections to external websites (Sveriges Riksbank’s API). Sometimes firewalls can block this. Contact your hosting provider if you suspect this.

**Q2: I’ve updated the markup percentages, but the prices on my store haven’t changed.**
A2:

- **Have you saved the settings?** Always click the “Save” button after making changes on the module configuration page.
- **Has the cron job run since you saved?** The changes will only take effect after the module performs its next update cycle. You can either wait for your scheduled cron job or manually trigger an update by visiting the Cron Job URL in your browser.
- **Clear PrestaShop Cache:** Sometimes PrestaShop’s cache can hold onto old data. Go to **Advanced Parameters > Performance**, and click “Clear cache” in the top right.

**Q3: The exchange rates seem incorrect or are not what I expect from Sveriges Riksbank.**
A3:

- **Check your Markup/Markdown settings:** Ensure you haven’t accidentally set a high markup or markdown percentage that’s skewing the rates.
- **Verify Sveriges Riksbank’s official rates:** Compare the rates in your store (after an update) with the official rates published on Sveriges Riksbank’s website to see if there’s a discrepancy.
- **Module’s base currency:** The module fetches rates relative to SEK. Ensure your PrestaShop’s default currency is correctly set up if you expect a different base.

**Q4: Will this module work with my custom theme?**
A4: Yes, this module operates entirely in the background and does not add any visual elements or modify any templates on the front office. Therefore, it is fully compatible with any PrestaShop theme, custom or default. Its function is purely data-driven (updating exchange rates).

**Q5: How do I add a new currency to my store so this module can manage it?**
A5:

1. Go to **International > Currencies** in your PrestaShop Back Office.
2. Click “Add new currency” (or the plus icon).
3. Fill in the details for the new currency (ISO code, symbol, exchange rate relative to your default currency).
4. Once added and enabled, the new currency will appear in the “Sveriges Riksbank - currency exchange rates” module’s configuration page, allowing you to set its markup/markdown.

The module follows a standard PrestaShop module architecture, primarily focusing on back-office configuration and front-office cron job execution. It leverages PrestaShop’s configuration system for settings storage and `ModuleFrontController` for handling the cron job request. The core logic resides in the main module file, which handles installation, uninstallation, and the `getContent()` method for the configuration form. The module’s primary function is to fetch external data (currency rates) and update PrestaShop’s `Currency` object data.
