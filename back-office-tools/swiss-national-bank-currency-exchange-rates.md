# Swiss National Bank - currency exchange rates

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for fetching external data. Your hosting environment must also support CRON jobs for automated updates.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, click “Configure” to access the module’s main settings page. This is where you will define how the module fetches and applies exchange rates.

#### **1. CRON URL**

- **What this setting does:** This displays the unique URL that you need to set up as a CRON job on your web server. When this URL is accessed, the module will automatically fetch the latest exchange rates from the Swiss National Bank and update them in your PrestaShop store.
- **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module.
  - *When correctly set up as a CRON job:* Your exchange rates will be automatically updated at the frequency you define (e.g., daily, hourly).
  - *When NOT set up as a CRON job:* Your exchange rates will not be automatically updated, and you will have to manually trigger the update by visiting this URL in your browser, which defeats the purpose of automation.
- **Recommended value:** Copy this URL and set it up as a CRON job on your hosting server.
- **Merchant scenario / example:** You want your exchange rates to update every morning at 3 AM. You copy this URL and add it to your hosting control panel’s CRON job scheduler, set to run daily at 3 AM.

#### **2. Exchange Rate Margin (%)**

- **What this setting does:** This allows you to add a percentage margin to the exchange rates fetched from the Swiss National Bank. This margin is applied on top of the base rate.
- **Effect of changing this setting:**
  - *When set to 0 (default):* Exchange rates will be updated exactly as provided by the SNB.
  - *When set to a positive value (e.g., 2):* The exchange rate will be increased by that percentage. For example, if the SNB rate is 1 EUR = 1.10 CHF, and you set a 2% margin, your store will use 1 EUR = 1.122 CHF (1.10 \* 1.02). This means products priced in CHF will appear slightly more expensive when converted to EUR.
- **Recommended value:** Start with 0. Only increase if you need to account for payment gateway fees, currency conversion costs, or to build a small profit margin into your international pricing.
- **Merchant scenario / example:** Your payment processor charges a 1.5% fee for international currency conversions. To cover this cost, you set the “Exchange Rate Margin” to 1.5%. This ensures your profit margins aren’t eroded by conversion fees.

#### **3. Save Button**

- **What this setting does:** This button saves any changes you’ve made to the “Exchange Rate Margin” setting.
- **Effect of changing this setting:** Clicking “Save” applies your margin setting. The CRON URL is static and does not require saving.
- **Recommended value:** Always click “Save” after adjusting the margin.
- **Merchant scenario / example:** You’ve decided to add a 1% margin. After typing “1” into the margin field, you click “Save” to ensure this setting is applied for future rate updates.

## 10. Developer & Webmaster Guide (Technical Architecture & Code Map)

### 10.1 Architecture Overview

The module follows a minimalist PrestaShop module architecture. Its primary function is to periodically fetch exchange rates from an external API (Swiss National Bank) and update the `currency` table in the PrestaShop database. The core logic resides in the main module file (`snbrates/cronjob.php`) and is triggered by a front controller, designed to be called by a CRON job. It uses PrestaShop’s `Configuration` class for storing settings and `Currency` ObjectModel for updating rates.

### 10.2 Controllers (`controllers/`)

- **Front-Office Controllers**: These controllers are designed to be accessed externally, primarily by CRON jobs.

  - `controllers/front/cronjob.php`

    - **Class name & parent class:** `SnbratesCronjobModuleFrontController` extends `ModuleFrontController`.
    - **Responsibility:** This is the main entry point for the automated rate update. When this controller’s URL is accessed (e.g., `yourstore.com/module/snbrates/cronjob`), it executes the logic to:
      1. Fetch the latest exchange rates from the configured SNB API endpoint.
      2. Apply the configured margin (if any).
      3. Update the `conversion_rate` for each active currency in the PrestaShop database, using CHF as the base.
      4. It does not render any visual output to the browser, typically returning a simple success/failure message or redirecting.
  - `controllers/front/index.php`

    - **Class name & parent class:** `SnbratesIndexModuleFrontController` extends `ModuleFrontController`.
    - **Responsibility:** This is a placeholder controller, often included in modules but not directly used for the core functionality of this specific module. It might be used for simple redirects or to prevent directory listing if accessed directly, but it does not contain specific business logic for rate updates.
- **Back-Office Admin Controllers**: None. The module’s configuration is handled directly within the main module file’s `getContent()` method.

### 10.3 Core Classes & Models (`classes/`)

The module does not introduce any custom classes or ObjectModels in the `classes/` directory. It directly leverages PrestaShop’s core `Currency` ObjectModel to manage currency data and `Configuration` for module settings.

### 10.4 JavaScript Assets (`views/js/`)

None. The module does not use any custom JavaScript.

### 10.5 CSS Stylesheets (`views/css/`)

None. The module does not use any custom CSS.

### 10.6 Smarty Template Structure (`views/templates/`)

- **Admin templates (`views/templates/admin/`)**:
  - `views/admin.tpl`
    - **Purpose:** This template is rendered by the `getContent()` method of the main module file (`snbrates/cronjob.php`) to display the module’s configuration form in the PrestaShop Back Office.
    - **Content:** It typically includes the form fields for the “CRON URL” (display only) and “Exchange Rate Margin (%)” (input field), along with the “Save” button. It uses standard PrestaShop helper functions for form rendering.

### 10.7 Database Schema & Hooks Map

- **Database Tables**:

  - The module does not create any custom database tables.
  - It interacts with the core PrestaShop `ps_currency` table, specifically updating the `conversion_rate` column for active currencies.
  - It stores its configuration settings (e.g., `SNBRATES_MARGIN`) in the `ps_configuration` table.
- **Registered Hooks Table**:
  The module does not explicitly register any front-office display hooks (like `displayHeader`, `displayRightColumn`, `displayFooter`, `displayProductButtons`, etc.) as its primary function is background data processing. The “Front-Office Hooks: Header, Columns, Product, or Footer” mentioned in the prompt might refer to a general capability or a misunderstanding, as the module’s core function doesn’t involve rendering content in these areas.

  The module implicitly uses the following:

  | Hook Name | Execution Timing | Technical Purpose |
  | --- | --- | --- |
  | `actionModuleInstall` | During module installation | Sets default configuration values. |
  | `actionModuleUninstall` | During module uninstallation | Cleans up configuration values. |
  | (Internal) `ModuleFrontController` dispatch | When the CRON URL is accessed | Triggers the rate update logic. |
