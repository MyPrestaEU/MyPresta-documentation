# Html box

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 7.1 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for a PrestaShop installation and are sufficient for this module.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure > Html box)

This is the main configuration screen where you define the content for your HTML boxes and where they appear.

#### General Settings

- **Enable SSL (https) for this module?** (`htmlbox_ssl`)

  - **What this setting does:** Determines if the module’s content should be loaded securely via HTTPS.
  - **Effect of changing this setting:**
    - *When enabled (YES):* Ensures that any content generated by this module is served over HTTPS, preventing “mixed content” warnings in browsers if your store uses SSL.
    - *When disabled (NO):* Content might be served over HTTP, which can cause security warnings on HTTPS-enabled stores.
  - **Recommended value:** **YES**
  - **Merchant scenario / example:** If your store uses HTTPS (which it should!), enabling this ensures your custom content doesn’t trigger security alerts for your customers.
- **Disable TinyMCE editor?** (`htmlbox_disabletiny`)

  - **What this setting does:** Controls whether the rich text editor (TinyMCE) is used for inputting your HTML content.
  - **Effect of changing this setting:**
    - *When enabled (YES):* You will see a plain text area for entering your HTML, JavaScript, or CSS. This is useful if you are pasting complex code that TinyMCE might try to “clean up” or if you prefer to write raw HTML.
    - *When disabled (NO):* You will have a user-friendly rich text editor, similar to a word processor, allowing you to format text, add images, and create links without writing HTML directly.
  - **Recommended value:** **NO** (unless you are a developer or pasting complex code).
  - **Merchant scenario / example:** If you want to quickly add a bolded text announcement, keep it disabled. If you’re pasting a Facebook widget code, enable it to prevent the editor from altering your code.
- **Show only for logged in customers?** (`htmlbox_logged`)

  - **What this setting does:** Restricts the visibility of the HTML box content to only customers who are logged into their accounts.
  - **Effect of changing this setting:**
    - *When enabled (YES):* Only registered and logged-in customers will see the content of the HTML box.
    - *When disabled (NO):* All visitors, whether logged in or not, will see the content.
  - **Recommended value:** **NO** (unless you have specific content for logged-in users).
  - **Merchant scenario / example:** You might enable this if you want to display a special loyalty program message or exclusive offers only visible to your existing customer base.
- **Show only for NOT logged in customers?** (`htmlbox_unlogged`)

  - **What this setting does:** Restricts the visibility of the HTML box content to only customers who are *not* logged into their accounts.
  - **Effect of changing this setting:**
    - *When enabled (YES):* Only visitors who are not logged in will see the content of the HTML box.
    - *When disabled (NO):* All visitors, whether logged in or not, will see the content.
  - **Recommended value:** **NO** (unless you have specific content for guests).
  - **Merchant scenario / example:** You could enable this to display a “Login or Register for exclusive offers” message to encourage new sign-ups or returning customers to log in.

#### HTML Box Content Fields

These fields are where you enter the actual HTML, JavaScript, or CSS content for each specific hook. Each field corresponds to a different location in your store.

- **HTML for Header (displayTop, displayNav1, displayNav2)** (`htmlbox_header`)

  - **What this setting does:** This is the content that will appear in the header section of your store. Depending on your theme, this could be `displayTop`, `displayNav1`, or `displayNav2`.
  - **Effect of changing this setting:** The content you enter here will be visible at the very top of your website.
  - **Recommended value:** Leave empty if not needed.
  - **Merchant scenario / example:** A site-wide announcement banner (“Free shipping on all orders over $50!”), a small social media icon bar, or a custom search bar.
- **HTML for Top Column (displayTopColumn)** (`htmlbox_top`)

  - **What this setting does:** This content appears just below the header, often spanning the full width of the main content area.
  - **Effect of changing this setting:** The content you enter here will be prominently displayed at the top of your main content area, typically above the main product listings or homepage content.
  - **Recommended value:** Leave empty if not needed.
  - **Merchant scenario / example:** A large promotional banner for a seasonal sale, a featured product slider, or a video introduction to your brand.
- **HTML for Left Column (displayLeftColumn)** (`htmlbox_leftcol`)

  - **What this setting does:** This content appears in the left sidebar of your store (if your theme has one and it’s enabled).
  - **Effect of changing this setting:** The content you enter here will be displayed in the left column, alongside other modules like category filters or navigation.
  - **Recommended value:** Leave empty if not needed.
  - **Merchant scenario / example:** A “Shop by Brand” list, a newsletter signup form, a small ad for a specific product category, or a Facebook Like Box.
- **HTML for Right Column (displayRightColumn)** (`htmlbox_rightcol`)

  - **What this setting does:** This content appears in the right sidebar of your store (if your theme has one and it’s enabled).
  - **Effect of changing this setting:** The content you enter here will be displayed in the right column, similar to the left column.
  - **Recommended value:** Leave empty if not needed.
  - **Merchant scenario / example:** A “Bestsellers” list, a customer service contact block, a Pinterest feed, or a “Recently Viewed Products” section.
- **HTML for Footer (displayFooter)** (`htmlbox_footercol`)

  - **What this setting does:** This content appears in the footer section at the bottom of every page.
  - **Effect of changing this setting:** The content you enter here will be visible at the very bottom of your website.
  - **Recommended value:** Leave empty if not needed.
  - **Merchant scenario / example:** Payment method logos, trust seals, a short “About Us” blurb, social media links, or a custom copyright notice.
- **HTML for Homepage (displayHome)** (`htmlbox_homecol`)

  - **What this setting does:** This content is specifically displayed on your store’s homepage.
  - **Effect of changing this setting:** The content you enter here will be a central part of your homepage layout.
  - **Recommended value:** Leave empty if not needed.
  - **Merchant scenario / example:** A grid of featured categories, a “Why Shop With Us” section, customer testimonials, or a large call-to-action button.
- **HTML for Body (displayBody)** (`htmlbox_body`)

  - **What this setting does:** This content is injected into the `<body>` tag of your HTML, typically at the very end before the closing `</body>` tag. It’s often used for global scripts or elements that need to be available across the entire site but aren’t visually tied to a specific section.
  - **Effect of changing this setting:** The content will be present on every page of your store, but its visual placement might depend on your theme’s CSS. It’s excellent for tracking codes or pop-ups.
  - **Recommended value:** Leave empty if not needed.
  - **Merchant scenario / example:** Google Analytics tracking code, Facebook Pixel, a global cookie consent banner (if not handled by another module), or a chat widget script.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My custom HTML isn’t showing up, or it looks broken.**
A:

1. **Check the Hook:** Ensure you’ve entered the content in the correct HTML box field for the desired location (e.g., `HTML for Homepage` for the homepage).
2. **Clear Cache:** Go to **Advanced Parameters > Performance** in your PrestaShop Back Office and click “Clear cache” (or “Clear Smarty cache” in older versions). PrestaShop often caches content, and new module settings might not appear immediately.
3. **Inspect HTML:** If you’re comfortable, use your browser’s developer tools (F12) to inspect the area where the content should be. Look for errors in the console or see if your HTML is present but styled incorrectly.
4. **TinyMCE Interference:** If you’re pasting complex code (especially JavaScript or iframes), try enabling “Disable TinyMCE editor?” to ensure the editor isn’t stripping out or altering your code.

**Q: The content appears, but it doesn’t look good on mobile.**
A: The module itself is responsive, but the *content you add* needs to be responsive too.

1. **Use Responsive HTML/CSS:** If you’re writing custom HTML, ensure you’re using responsive design principles (e.g., `max-width: 100%` for images, CSS media queries).
2. **Third-Party Widgets:** If you’re embedding a widget (like Facebook or Twitter), check if the widget provider offers responsive embed codes or settings.
3. **Simple Content:** For critical mobile content, keep it simple: plain text, small images, and clear calls to action.

**Q: I’ve added JavaScript, but it’s not executing.**
A:

1. **Placement:** JavaScript added to the `HTML for Body` field is generally the safest place for global scripts, as it’s loaded at the end of the page.
2. **Syntax Errors:** Check your JavaScript code for any syntax errors. A single error can prevent the entire script from running.
3. **jQuery Conflicts:** If your script relies on jQuery, ensure it’s loaded correctly and that there are no conflicts with PrestaShop’s jQuery version. You might need to wrap your code in `(function($){ /* your code */ })(jQuery);` or use `jQuery.noConflict();`.
4. **External Scripts:** If you’re linking to an external `.js` file, ensure the URL is correct and accessible.

**Q: How do I translate the content in my HTML boxes for different languages?**
A: The module’s current version does not offer built-in multi-language fields for each HTML box. To achieve multi-language content, you have two main options:

1. **Manual Language Detection (Advanced):** You can embed conditional logic within your HTML box content using Smarty variables (if your theme allows Smarty processing in hooks) or JavaScript to detect the current language and display different content. This is a more advanced solution.
   *Example (Smarty):*

   ```
   {if $language.iso\_code == 'en'} <p>Welcome to our English store!</p>{elseif $language.iso\_code == 'fr'} <p>Bienvenue dans notre boutique française !</p>{/if}
   ```
2. **Separate Modules (Workaround):** For critical content, you might consider installing separate instances of the “Html box” module (if allowed by the module developer or by duplicating the module) and assigning each to a specific language, then managing their display through PrestaShop’s module positions. This is a more complex workaround.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

This section provides a detailed technical overview for developers and webmasters working with the Html box module.

### 4.1 Architecture Overview

The `Html box` module is a straightforward PrestaShop module primarily designed to inject custom HTML/JS/CSS content into various front-office hooks. It follows a classic PrestaShop module structure, leveraging the `Module` class for installation, uninstallation, and configuration, and utilizing the `hook` methods to render content in the front office. Configuration is managed through the `getContent()` method, which renders a standard PrestaShop configuration form. The module stores its content directly in the `ps_configuration` table.

### 4.2 Controllers (`controllers/`)

This module does **not** contain any custom Front-Office or Back-Office Admin Controllers. All functionality, including configuration and front-office rendering, is handled directly within the main `htmlbox.php` module file.

### 4.3 Core Classes & Models (`classes/`)

This module does **not** define any custom classes or `ObjectModel` instances. All data is stored as configuration values.

### 4.4 JavaScript Assets (`views/js/`)

- **`htmlbox/tinymce16.inc.js`**
  - **Scope:** Back-office (specifically the module configuration page).
  - **Purpose:** This file is responsible for initializing and configuring the TinyMCE rich text editor within the module’s configuration form. It transforms standard `<textarea>` elements into a user-friendly WYSIWYG editor, allowing merchants to format text, insert images, and manage HTML content without direct coding. It likely includes custom settings to integrate TinyMCE with PrestaShop’s file manager for image uploads.
  - **Developer Notes:** If `htmlbox_disabletiny` is enabled, this script will not be loaded or its functionality will be bypassed. Developers wishing to customize the TinyMCE experience (e.g., adding custom buttons, changing toolbar layout) would need to modify this file or override its loading/configuration.

### 4.5 CSS Stylesheets (`views/css/`)

This module does **not** include any custom CSS files. Any styling for the injected HTML content must be provided within the HTML content itself (inline styles or `<style>` tags) or by the active PrestaShop theme.

### 4.6 Smarty Template Structure (`views/templates/`)

- **`views/templates/hook/html.tpl`**
  - **Scope:** Front-office.
  - **Hook Rendering:** This is the primary template file used by the module to render the custom HTML content in all registered front-office hooks.
  - **Content:** It likely contains a simple structure to output the `$html_content` variable, which is passed from the module’s hook methods.
  - **Developer Notes:** This template is minimal. The actual content is dynamically loaded from the `ps_configuration` table based on the hook. Developers can override this template in their theme (e.g., `themes/yourtheme/modules/htmlbox/html.tpl`) to wrap the content in custom `div`s, add specific classes, or apply conditional logic, though most customization will be done directly in the HTML box content itself.
