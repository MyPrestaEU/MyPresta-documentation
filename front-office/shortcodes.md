# Shortcodes

## 1. Requirements & Compatibility
- **Supported PrestaShop Versions**: PrestaShop 1.5.x, 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for a PrestaShop installation and are sufficient for this module.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)
After installing the module, navigate to **Modules > Module Manager** and search for "Shortcodes". Click on the "Configure" button to access its settings.

The configuration page for the Shortcodes module is straightforward and focuses on a single, crucial setting:

#### Disable all shortcodes
-   **What this setting does:** This is a master switch that controls whether the module processes and replaces any shortcodes on your entire website.
-   **Effect of changing this setting:**
    -   *When enabled (set to "On"):* The module will actively scan your content and theme files for recognized shortcodes (e.g., `[products]`, `[categories]`, `[html]`) and replace them with the corresponding dynamic content. This is the intended operational mode for the module.
    -   *When disabled (set to "Off"):* The module will stop processing all shortcodes. Any shortcodes you have placed in your content or theme files will simply appear as plain text (e.g., `[products]` will be visible as `[products]` to your customers) and will not be replaced by dynamic content.
-   **Recommended value:** **On**
-   **Merchant scenario / example:**
    -   You would set this to "On" to activate the shortcode functionality and display your dynamic content.
    -   You might temporarily set this to "Off" if you are debugging an issue, performing maintenance, or if you want to disable all dynamic content generated by shortcodes across your store without uninstalling the module. Remember to save your changes after toggling this setting.

:::tip
After changing any settings, always click the "Save" button to apply your modifications.
:::

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q1: My shortcodes are showing up as plain text (e.g., `[products]`) instead of dynamic content. What's wrong?**
**A1:**
1.  **Check Module Status:** Go to **Modules > Module Manager** and ensure the "Shortcodes" module is installed and enabled.
2.  **Check Module Configuration:** Go to the module's configuration page and make sure "Disable all shortcodes" is set to **"On"**.
3.  **Clear Cache:** Sometimes PrestaShop's cache can prevent changes from appearing immediately. Go to **Advanced Parameters > Performance** and click "Clear cache" (or "Clear Smarty cache" in older versions).
4.  **Correct Shortcode Syntax:** Double-check that you've typed the shortcode exactly as required, including brackets `[]` and any parameters (e.g., `[products type="new"]`). Any typo will prevent it from being processed.

**Q2: The dynamic content (e.g., product carousel) isn't styled correctly or looks broken on my theme.**
**A2:**
This usually indicates a CSS conflict or missing styling specific to your theme.
1.  **Theme Compatibility:** While the module provides basic styling, custom themes might override or lack styles for certain elements.
2.  **Developer Assistance:** You may need a web developer to inspect the page using browser developer tools (F12) to identify CSS conflicts and add custom CSS rules to your theme to ensure the shortcode output integrates visually. The module's CSS file (`cmsproductspro.css`) can be a starting point for reference.

**Q3: Can I use shortcodes in multi-language stores?**
**A3:** Yes, shortcodes themselves are language-agnostic. The content they generate (e.g., product names, descriptions) will automatically be displayed in the language selected by the customer, provided your products and categories have translations for that language. When placing shortcodes in CMS pages or product descriptions, ensure you are editing the content for the correct language in the back office.

**Q4: I've added a shortcode to a new CMS page, but it's not appearing on the front office.**
**A4:**
1.  **Page Status:** Ensure your CMS page is enabled and visible in your navigation menu or linked from another page.
2.  **Cache:** Clear your PrestaShop cache (**Advanced Parameters > Performance**).
3.  **Shortcode Placement:** Verify that the shortcode is placed in a content area that is actually rendered by your theme for that CMS page. Some themes might have specific content blocks.

**Q5: What shortcodes are available and what parameters can I use?**
**A5:** The module's documentation (this guide) or the module's configuration page (if it lists them) should detail the available shortcodes. Common shortcodes include:
-   `[products]` (for various product listings like new, bestsellers, specific IDs)
-   `[categories]` (for displaying category lists)
-   `[html]` (for embedding custom HTML)
-   `[imageManufacturer]` (for displaying manufacturer images)
You'll need to refer to the module's specific implementation for exact parameters (e.g., `limit`, `carousel`, `id`, `type`).

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

This section provides a technical overview for developers and webmasters looking to understand, debug, or extend the Shortcodes module.

### 4.1 Architecture Overview
The Shortcodes module (`cmsproductspro`) operates primarily as a content filter. It hooks into PrestaShop's output rendering process to intercept HTML content before it's sent to the browser. It then uses regular expressions to find and replace predefined shortcode patterns with dynamically generated HTML content. The module's configuration is minimal, focusing on a global enable/disable switch. Content generation logic is encapsulated within the main module class, leveraging PrestaShop's core functionalities for data retrieval (products, categories, manufacturers).

### 4.2 Controllers (`controllers/`)
This module does **not** contain any custom Front-Office or Back-Office Admin Controllers. All configuration and content processing logic is handled within the main module file (`cmsproductspro.php`).

### 4.3 Core Classes & Models (`classes/`)
This module does **not** define any custom classes or `ObjectModel`s in a `classes/` directory. All core logic resides within the `cmsproductspro.php` file.

### 4.4 JavaScript Assets (`views/js/`)
This module does **not** contain any custom JavaScript files. Any dynamic behavior (like carousels) would typically rely on existing PrestaShop or theme-provided JavaScript libraries (e.g., Owl Carousel, Slick Carousel) if the shortcode output includes such components.

### 4.5 CSS Stylesheets (`views/css/`)
-   **`cmsproductspro/cmsproductspro.css`**
    *   **Scope:** Front-office customer styling.
    *   **Main UI components and containers it styles:** This stylesheet provides basic styling for the HTML output generated by the shortcodes. This includes:
        *   Product grids and carousels (e.g., `.cmsproductspro-products-grid`, `.cmsproductspro-carousel`).
        *   Individual product items (e.g., `.cmsproductspro-product-item`, `.cmsproductspro-product-image`, `.cmsproductspro-product-name`, `.cmsproductspro-product-price`).
        *   Category lists (e.g., `.cmsproductspro-categories-list`, `.cmsproductspro-category-item`).
        *   Manufacturer images (e.g., `.cmsproductspro-manufacturer-image`).
        *   General layout and responsiveness for these elements.
    *   **Key CSS class selectors developers can override:** Developers can target classes like `.cmsproductspro-products-grid`, `.cmsproductspro-product-item`, `.cmsproductspro-product-name`, `.cmsproductspro-product-price`, `.cmsproductspro-categories-list`, `.cmsproductspro-category-item`, `.cmsproductspro-manufacturer-image` to customize the appearance of the shortcode-generated content within their theme.

### 4.6 Smarty Template Structure (`views/templates/`)
The module uses several Smarty templates to render the dynamic content for various shortcodes. These templates are located in `views/templates/`.

-   **Hook templates (`views/templates/hook/`)**: This module does not explicitly use a `hook/` subdirectory for its templates. The templates are directly within `views/templates/` and are rendered based on the detected shortcode.

-   **Admin templates (`views/templates/admin/`)**: This module does not contain any specific admin templates beyond the standard configuration form handled by `getContent()`.

-   **Front-office templates (`views/templates/front/`)**:
    *   **`cmsproductspro/categories.tpl`**:
        *   **Purpose:** Renders a list of categories, typically used by a `[categories]` shortcode.
        *   **Variables:** Expects variables like `$categories` (an array of category objects), `$display_subcategories`, `$image` etc.
        *   **Output:** Generates HTML for a grid or list of categories, potentially with images and links.
    *   **`cmsproductspro/html.tpl`**:
        *   **Purpose:** Renders raw HTML content, used by an `[html]` shortcode.
        *   **Variables:** Expects a `$content` variable containing the HTML string to be outputted.
        *   **Output:** Directly outputs the provided HTML content.
    *   **`cmsproductspro/imageManufacturer.tpl`**:
        *   **Purpose:** Displays a manufacturer's image, used by an `[imageManufacturer]` shortcode.
        *   **Variables:** Expects `$manufacturer` (an object with manufacturer details, including image path) and potentially `$link` for the manufacturer page.
        *   **Output:** Generates an `<img>` tag for the manufacturer's logo, often wrapped in a link.
    *   **`cmsproductspro/productGallery.tpl`**:
        *   **Purpose:** Renders a gallery of products, potentially with specific layout or features. This might be a more generic product display template.
        *   **Variables:** Expects `$products` (an array of product objects) and other display options.
        *   **Output:** HTML structure for a product gallery.
    *   **`cmsproductspro/products-carousel.tpl`**:
        *   **Purpose:** Renders a product list specifically designed to be used within a carousel component.
        *   **Variables:** Expects `$products` (array of product objects) and potentially carousel-specific options.
        *   **Output:** HTML structure for a product list, often with classes suitable for a JavaScript carousel library.
    *   **`cmsproductspro/products.tpl`**:
        *   **Purpose:** Renders a general list or grid of products, used by a `[products]` shortcode.
        *   **Variables:** Expects `$products` (array of product objects) and other display options like `$grid_class`, `$item_class`.
        *   **Output:** HTML structure for a product grid or list.

### 4.7 Database Schema & Hooks Map

-   **Database Tables**: This module does **not** create any custom database tables. Its configuration is stored in the `ps_configuration` table using keys like `CMSPRODUCTSPRO_HIDE` (for the "Disable all shortcodes" setting).

-   **Registered Hooks Table**:

| Hook Name | Execution Timing | Technical Purpose |
|---|---|---|
| `actionOutputHTMLBefore` | Executed just before the final HTML output is sent to the browser. | This is the primary hook where the module intercepts the entire page content, scans for shortcodes, and performs replacements. |
| `displayHeader` | Executed in the `<head>` section of the HTML. | Used to include necessary CSS files (`cmsproductspro.css`) for the shortcode-generated content. |
| `actionAjaxDieProductControllerdisplayAjaxQuickviewBefore` | Executed before the `displayAjaxQuickview` method in `ProductController` (for quick view modals). | This hook ensures that shortcodes are also processed and replaced within the content loaded via AJAX for product quick views, maintaining consistency. |
