# Amazon connect (register + login)

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.6.x, 1.7.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for secure API communication.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

This is the main configuration screen for the Amazon Login module, where you will link your PrestaShop store to your Amazon Developer account.

- **aml\_ClientID (Amazon Client ID)**
  - **What this setting does:** This is a unique identifier provided by Amazon when you register your application (your PrestaShop store) with their Login with Amazon service. It tells Amazon which application is requesting user authentication.
  - **Effect of changing this setting:**
    - *When correctly entered:* Your “Login with Amazon” button will function correctly, allowing customers to authenticate via their Amazon account.
    - *When incorrect or empty:* The “Login with Amazon” button will not work, or customers will encounter an error when trying to use it.
  - **Recommended value:** The Client ID obtained from your Amazon Developer Console. This field cannot be left empty for the module to function.
  - **Merchant scenario / example:** You’ve registered your PrestaShop store as an application on the Amazon Developer Console. Amazon provides you with a “Client ID” (e.g., `amzn1.oauth-client.xxxxxxxxxxxxxxxxxxxxxxxxxxxx`). You must copy and paste this exact ID into this field.
- **aml\_ClientSecret (Amazon Client Secret)**
  - **What this setting does:** This is a confidential key also provided by Amazon, used in conjunction with the Client ID to authenticate your application securely with Amazon’s servers. It ensures that only your legitimate application can request user data.
  - **Effect of changing this setting:**
    - *When correctly entered:* Your module can securely communicate with Amazon’s API to verify user identities.
    - *When incorrect or empty:* The authentication process will fail, as your store cannot securely identify itself to Amazon.
  - **Recommended value:** The Client Secret obtained from your Amazon Developer Console. This field cannot be left empty for the module to function.
  - **Merchant scenario / example:** Alongside the Client ID, Amazon also gives you a “Client Secret” (e.g., `yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy`). This secret must be kept confidential and entered accurately here.
- **aml\_RedirectURI (Amazon Redirect URI)**
  - **What this setting does:** This is the URL on your PrestaShop store where Amazon will redirect the user’s browser *after* they have successfully logged in or authorized your application on Amazon’s site. It’s crucial for the secure flow of the authentication process.
  - **Effect of changing this setting:**
    - *When correctly configured on both ends (module and Amazon Developer Console):* Users are seamlessly returned to your store after Amazon login.
    - *When incorrect:* Users will encounter an error after logging in with Amazon, or they will not be redirected back to your store correctly. This URI must also be registered in your Amazon Developer Console settings for your application.
  - **Recommended value:** This should typically be automatically generated by the module or be a specific URL like `https://yourstore.com/module/amlogin/ajax_amlogin` (verify the exact path provided by the module or Amazon’s documentation). Ensure it matches the URI you registered in your Amazon Developer Console.
  - **Merchant scenario / example:** When setting up your application on the Amazon Developer Console, you’ll be asked for “Allowed Return URLs.” You must enter the exact URL that this module uses for redirection (e.g., `https://www.yourstore.com/module/amlogin/ajax_amlogin`).
- **Display Amazon Login Button in Header**
  - **What this setting does:** Controls whether the “Login with Amazon” button appears in your store’s header section.
  - **Effect of changing this setting:**
    - *When enabled:* The button will be visible in the header, offering immediate access to Amazon login.
    - *When disabled:* The button will not appear in the header.
  - **Recommended value:** YES, for maximum visibility and ease of access.
  - **Merchant scenario / example:** You want customers to see the Amazon login option as soon as they land on your site, so you enable this.
- **Display Amazon Login Button in Left Column**
  - **What this setting does:** Controls whether the “Login with Amazon” button appears in your store’s left sidebar column.
  - **Effect of changing this setting:**
    - *When enabled:* The button will be visible in the left column, often alongside other navigation or account blocks.
    - *When disabled:* The button will not appear in the left column.
  - **Recommended value:** YES, if your theme uses a left column and you want persistent visibility.
  - **Merchant scenario / example:** Your store has a prominent left column, and you want to offer the Amazon login option there as customers browse categories.
- **Display Amazon Login Button in Right Column**
  - **What this setting does:** Controls whether the “Login with Amazon” button appears in your store’s right sidebar column.
  - **Effect of changing this setting:**
    - *When enabled:* The button will be visible in the right column.
    - *When disabled:* The button will not appear in the right column.
  - **Recommended value:** YES, if your theme uses a right column and you want persistent visibility.
  - **Merchant scenario / example:** Similar to the left column, if your theme uses a right column, you might place the button there for visibility.
- **Display Amazon Login Button on Product Page**
  - **What this setting does:** Controls whether the “Login with Amazon” button appears on individual product detail pages.
  - **Effect of changing this setting:**
    - *When enabled:* The button will be shown on product pages, potentially near the “Add to Cart” button or product description.
    - *When disabled:* The button will not appear on product pages.
  - **Recommended value:** YES, as it can encourage immediate login or registration before adding to cart.
  - **Merchant scenario / example:** A customer is viewing a product and decides they want to buy it. Seeing the Amazon login button allows them to quickly log in or create an account before proceeding to checkout.
- **Display Amazon Login Button in Footer**
  - **What this setting does:** Controls whether the “Login with Amazon” button appears in your store’s footer section.
  - **Effect of changing this setting:**
    - *When enabled:* The button will be visible in the footer, providing an alternative login point.
    - *When disabled:* The button will not appear in the footer.
  - **Recommended value:** NO, unless you have a specific design reason. Other locations offer better visibility.
  - **Merchant scenario / example:** You want to offer the Amazon login option but prefer it not to be too prominent, so you place it in the footer.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: The Amazon Login button appears, but nothing happens when I click it, or I get an error.**
A: This usually indicates an issue with your `aml_ClientID`, `aml_ClientSecret`, or `aml_RedirectURI`.
- **Check 1:** Double-check that you’ve copied the Client ID and Client Secret exactly from your Amazon Developer Console into the module’s configuration. Even a single character error will cause failure.
- **Check 2:** Verify that the `aml_RedirectURI` in the module configuration exactly matches one of the “Allowed Return URLs” you’ve registered in your Amazon Developer Console for your application. Pay attention to `http` vs `https` and trailing slashes.
- **Check 3:** Clear your PrestaShop cache (Advanced Parameters > Performance > Clear cache) and your browser cache.

**Q: My customers are redirected to Amazon, but then get an error or aren’t sent back to my store.**
A: This is almost certainly a `aml_RedirectURI` mismatch. Go to your Amazon Developer Console, find your application, and ensure the “Allowed Return URLs” list contains the *exact* URL that your PrestaShop module is configured to use. It must be an exact match, including `http/https` and any subdirectories.

**Q: The Amazon Login button doesn’t appear in the locations I’ve enabled.**
A:
- **Check 1:** Ensure the module is enabled and configured correctly in the Back Office.
- **Check 2:** Clear your PrestaShop cache (Advanced Parameters > Performance > Clear cache). Sometimes, template changes don’t reflect immediately.
- **Check 3:** Your theme might be overriding the standard PrestaShop hooks. If the button still doesn’t appear, you might need a web developer to manually insert the module’s hook call into your theme’s `.tpl` files (see Section 7.6 for relevant templates).

**Q: Does this module work with multi-language stores?**
A: Yes, the module should inherit PrestaShop’s multi-language capabilities for any text it displays. The Amazon login process itself is handled by Amazon and will typically adapt to the user’s Amazon account language settings.

**Q: Can I customize the look of the Amazon Login button?**
A: The module uses standard Amazon Login button assets. While you can’t change the core Amazon button design (as per Amazon’s branding guidelines), you can use custom CSS (see Section 7.5) to adjust its placement, margins, or the container around it to better fit your theme.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

### 4.1 Architecture Overview

The “Amazon connect (register + login)” module integrates Amazon’s Login with Amazon (LWA) service into PrestaShop. It primarily operates as a standard PrestaShop module, leveraging hooks to display the login button in various front-office locations. The core logic for handling the Amazon OAuth 2.0 flow (redirecting to Amazon, receiving the authorization code, exchanging it for an access token, and fetching user profile data) is encapsulated within the main module file and its associated AJAX controller. User data received from Amazon is then used to either log in an existing PrestaShop customer or create a new one.

### 4.2 Controllers (`controllers/`)

This module does not use dedicated front or admin controllers in the `controllers/` directory. All front-office AJAX requests and the main module configuration are handled by the main module file (`amlogin/ajax_amlogin.php`) which acts as a pseudo-controller for AJAX actions.

### 4.3 Core Classes & Models (`classes/`)

This module does not contain any custom classes or models in a dedicated `classes/` directory. The core logic resides within the main module file `amlogin/ajax_amlogin.php`.

### 4.4 JavaScript Assets (`views/js/`)

- `amlogin/js/amlogin.js`
  - **Scope:** Front-office.
  - **Description:** This script is responsible for initializing the Amazon Login SDK, handling the click events on the Amazon Login button, and managing the OAuth 2.0 flow. It likely uses the `amazon.Login.authorize` method to initiate the login process and handles the callback from Amazon. It will then make an AJAX call to the module’s backend to process the Amazon user data and log the customer into PrestaShop. It may also update the UI (e.g., show logged-in state) after successful authentication.

### 4.5 CSS Stylesheets (`views/css/`)

- `amlogin/css.css`
  - **Scope:** Front-office.
  - **Description:** General styling for the Amazon Login button and any associated UI elements. This might contain basic layout, padding, or margin adjustments.
- `amlogin/css/amlogin.css`
  - **Scope:** Front-office.
  - **Description:** Specific styling for the Amazon Login button, potentially including responsive adjustments or theme-specific overrides for PrestaShop 1.6.
- `amlogin/css/amlogin17.css`
  - **Scope:** Front-office.
  - **Description:** Specific styling tailored for PrestaShop 1.7 themes, addressing potential differences in default theme structures or CSS frameworks (e.g., Bootstrap 4 vs. Bootstrap 3). Developers can override these styles in their theme’s `custom.css` or by creating a child theme.

### 4.6 Smarty Template Structure (`views/templates/`)

The module utilizes a comprehensive set of Smarty templates to render the Amazon Login button across various PrestaShop hooks.

- **Hook templates (`views/templates/hook/`)**:
  - `amlogin/ajax-amlogin.tpl`: Likely used for AJAX responses or dynamic content related to the Amazon login process.
  - `amlogin/amlogin.tpl`: A generic template for the Amazon Login button, often included by other hook templates.
  - `amlogin/createAccountForm.tpl`: Renders the Amazon Login button within the standard PrestaShop account creation form.
  - `amlogin/createAccountTop.tpl`: Renders the Amazon Login button at the top of the account creation page.
  - `amlogin/dashboardZoneOne.tpl`: Renders the Amazon Login button in the customer dashboard’s first zone (e.g., `displayCustomerAccount`).
  - `amlogin/displayCustomerLoginFormAfter.tpl`: Renders the Amazon Login button after the standard customer login form.
  - `amlogin/displayNav.tpl`: Renders the Amazon Login button in the navigation bar (e.g., `displayNav` hook).
