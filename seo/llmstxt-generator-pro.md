# LLMS.txt Generator Pro

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 7.1 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL). Your server must also allow for file writing to the root directory for the `llms.txt` file to be generated.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure > LLMS.txt Generator Pro)

This is the main control panel for your LLMS.txt Generator Pro module. Here, you’ll define how your `llms.txt` file is generated and what content it includes.

#### General Settings

- **Enable LLMS.txt Generation:**

  - **What this setting does:** This is the master switch to activate or deactivate the module’s core functionality.
  - **Effect of changing this setting:**
    - *When enabled:* The module will generate and serve the `llms.txt` file according to your settings. AI crawlers will be able to access it.
    - *When disabled:* The `llms.txt` file will not be generated or served by the module. AI crawlers will not receive specific guidance from your store.
  - **Recommended value:** YES
  - **Merchant scenario / example:** You’ve just installed the module and want to start guiding AI bots. Enable this. If you need to temporarily stop AI guidance for maintenance, you can disable it here.
- **LLMS.txt File Type:**

  - **What this setting does:** Determines whether the `llms.txt` file is generated as a static file (written to your server) or dynamically served on demand.
  - **Effect of changing this setting:**
    - *Static:* The module writes a physical `llms.txt` file to your store’s root directory. This is generally faster for AI bots as it doesn’t require PHP processing on every request.
    - *Dynamic:* The `llms.txt` file is generated by PrestaShop’s PHP code every time an AI bot requests it. This ensures the most up-to-date content but can be slightly slower.
  - **Recommended value:** Static (for performance, unless you have frequent, real-time content changes that must be reflected instantly).
  - **Merchant scenario / example:** For most stores, static is fine. If you have a very high-traffic store with constantly changing product prices or stock, dynamic might be preferred, but consider the performance impact.
- **Generate llms-full.txt:**

  - **What this setting does:** Controls whether an additional, more comprehensive `llms-full.txt` file is also generated. This file typically includes more detailed or less restricted information than the standard `llms.txt`.
  - **Effect of changing this setting:**
    - *When enabled:* An `llms-full.txt` file will be created alongside `llms.txt`, offering AI crawlers a richer dataset.
    - *When disabled:* Only the standard `llms.txt` file will be generated.
  - **Recommended value:** YES (to provide maximum data to AI, unless you have specific reasons to restrict it).
  - **Merchant scenario / example:** You want AI models to have access to as much relevant information as possible about your products, including potentially less critical but still useful details.
- **Include Product Pages:**

  - **What this setting does:** Determines if individual product pages are listed in the `llms.txt` file.
  - **Effect of changing this setting:**
    - *When enabled:* URLs for all your active product pages will be included, making them discoverable by AI.
    - *When disabled:* Product pages will be excluded, meaning AI bots won’t be explicitly guided to them via `llms.txt`.
  - **Recommended value:** YES (Products are usually the core of an e-commerce store).
  - **Merchant scenario / example:** You want AI to help customers find specific products.
- **Include Category Pages:**

  - **Effect of changing this setting:**

#### Advanced Settings

- **Regeneration Schedule (Cron Job):**

  - **What this setting does:** Defines how often the `llms.txt` file should be automatically regenerated. This is crucial for keeping the file up-to-date without manual intervention.
  - **Effect of changing this setting:**
    - *Daily / Weekly / Monthly:* The module will provide a cron job URL. When this URL is accessed (e.g., by your hosting provider’s cron service), the `llms.txt` file will be rebuilt.
    - *Manual:* You will need to click the “Generate LLMS.txt” button manually each time you want to update the file.
  - **Recommended value:** Daily (for most active stores).
  - **Merchant scenario / example:** You add new products or update prices regularly. Setting a daily regeneration ensures AI crawlers always get the latest information. The module will display the cron URL you need to set up on your server.
- **Multistore Support:**

  - **What this setting does:** If you run a PrestaShop Multistore, this option allows you to generate separate `llms.txt` files for each of your stores or a single file for all stores.
  - **Effect of changing this setting:**
    - *Enabled:* The module will respect your Multistore context and generate files specific to each store’s content.
    - *Disabled:* The module might generate a single file based on the default store or behave unexpectedly in a Multistore environment.
  - **Recommended value:** YES (if you use Multistore).
  - **Merchant scenario / example:** You have different product catalogs or languages for each store in your Multistore setup, and you need distinct `llms.txt` files for each.
- **Cache Lifetime (minutes):**

  - **What this setting does:** Determines how long the generated `llms.txt` file is cached before it’s considered “stale” and needs regeneration (for dynamic file type).
  - **Effect of changing this setting:**
    - *Higher value:* Less frequent regeneration, potentially faster for AI bots but content might be slightly older.
    - *Lower value:* More frequent regeneration, ensuring fresher content but potentially higher server load.
  - **Recommended value:** 60 (1 hour) for dynamic, or irrelevant for static.
  - **Merchant scenario / example:** If you use dynamic generation and your product data changes hourly, set this to 60. If changes are less frequent, you can increase it.
- **Enable Analytics & Bot Tracking:**

  - **What this setting does:** Activates a feature to track when AI bots access your `llms.txt` file, providing insights into their activity.
  - **Effect of changing this setting:**
    - *When enabled:* The module will log accesses to the `llms.txt` file, which can be viewed in the module’s dashboard.
    - *When disabled:* No bot access data will be collected.
  - **Recommended value:** YES (Useful for understanding AI crawler activity).
  - **Merchant scenario / example:** You want to see how often AI models are crawling your store and which ones are most active.
- **Clear Cache Button:**

  - **What this setting does:** A manual button to clear any cached `llms.txt` files.
  - **Effect of changing this setting:** Immediately removes any stored `llms.txt` files, forcing a fresh regeneration on the next request (for dynamic) or when the “Generate LLMS.txt” button is clicked (for static).
  - **Recommended value:** Click when you make significant changes to your settings or product catalog and want to ensure the `llms.txt` file is immediately updated.
  - **Merchant scenario / example:** You’ve just added a major new product line and want AI to discover it right away, so you clear the cache and regenerate.
- **Generate LLMS.txt Button:**

  - **What this setting does:** A manual button to immediately generate or regenerate the `llms.txt` file based on your current settings.
  - **Effect of changing this setting:** The module processes your catalog and settings, then creates or updates the `llms.txt` file.
  - **Recommended value:** Click after making any configuration changes or when you need an immediate update, especially if using static file generation.
  - **Merchant scenario / example:** You’ve finished configuring all your exclusion rules and want to create the initial `llms.txt` file.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My `llms.txt` file isn’t appearing or updating.**
A:

1. **Check “Enable LLMS.txt Generation”:** Ensure this is set to YES in the module configuration.
2. **Check File Type:** If set to “Static”, ensure your server has write permissions to the PrestaShop root directory. Also, click the “Generate LLMS.txt” button manually.
3. **Cron Job:** If using a cron job, verify it’s correctly set up on your hosting and the URL provided by the module is accessible.
4. **Clear Cache:** Go to **Advanced Parameters > Performance** in PrestaShop and clear the Smarty cache. Then, try regenerating the `llms.txt` file.
5. **Module Dashboard:** Check the module’s dashboard for any error messages during generation.

**Q: I’ve made changes, but the `llms.txt` file doesn’t reflect them.**
A:

1. **Regenerate Manually:** Click the “Generate LLMS.txt” button in the module configuration.
2. **Cron Job Timing:** If you rely on a cron job, remember it only runs at scheduled intervals. Your changes will appear after the next scheduled run.
3. **Cache:** If you’re using dynamic generation, the `llms.txt` file might be cached. Click the “Clear Cache” button in the module, or clear PrestaShop’s cache under **Advanced Parameters > Performance**.

**Q: How do I know if AI bots are actually using my `llms.txt` file?**
A: Enable “Analytics & Bot Tracking” in the module settings. The module’s dashboard will then show you statistics on which AI user agents have accessed your `llms.txt` file and when.

**Q: The `llms.txt` file is too large or includes too many irrelevant URLs.**
A:

1. **Review Inclusion Settings:** Go through the “Include…” options and disable any content types you don’t want AI to index (e.g., Supplier Pages).
2. **Utilize Exclusion Filters:** Make extensive use of the “Exclude Products by…” filters (Category, Stock, Price, etc.) and “Exclude Specific URLs” to fine-tune the content.
3. **Per-Product/Category Overrides:** For very specific cases, use the exclusion checkboxes on individual product and category editing pages.

**Q: My custom theme doesn’t display the module’s features correctly (e.g., extra fields on product page).**
A: The module’s integration with product/category pages is standard. If you encounter issues, it’s likely a conflict with your custom theme or another module that heavily modifies the product/category edit forms.

1. **Check for Conflicts:** Temporarily disable other modules that modify product/category pages to see if the issue resolves.
2. **Theme Overrides:** Your theme might have template overrides that prevent the module’s extra fields from rendering. Contact your theme developer or a PrestaShop expert to investigate.
3. **Clear Cache:** Always clear PrestaShop’s cache after theme or module changes.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)

### 4.1 Architecture Overview

The LLMS.txt Generator Pro module follows a standard PrestaShop module architecture, leveraging MVC principles. It primarily operates through a main module class (`llmstxtpro/index.php`) for configuration and hook management, and a set of dedicated classes (`classes/`) for business logic, data handling, and file generation. Front controllers handle dynamic `llms.txt` serving and cron job execution. Configuration is stored in `ps_configuration` and custom tables.
