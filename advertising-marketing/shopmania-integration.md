# Shopmania Integration

## 1. Requirements & Compatibility
- **Supported PrestaShop Versions**: PrestaShop 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 7.1 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically required for general PrestaShop operation, but this module has minimal specific requirements beyond a standard PrestaShop hosting environment.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)
After installation, click "Configure" next to the "Shopmania Integration" module in your Module Manager. This will take you to the main configuration page.

The Shopmania Integration module is designed to be very straightforward, often requiring minimal configuration as it primarily focuses on generating a product feed.

| Setting / Option | Default / Recommended | Purpose & Impact |
|---|---|---|
| **ShopMania Feed URL** | Automatically generated | This is the direct link to the product feed generated by your module. You will need to copy this URL and provide it to ShopMania when setting up your merchant account with them. This URL is what ShopMania will use to regularly fetch your product data. |

**What this setting does:**
This section displays the URL that ShopMania will use to access your product data feed. This feed contains all the necessary information about your products (name, description, price, images, availability, etc.) in a format that ShopMania can understand and display on their platform.

**Effect of changing this setting:**
You cannot directly change this URL. It is automatically generated by the module based on your store's domain and the module's internal logic.

**Recommended value:**
Copy this URL exactly as it appears. Do not modify it.

**Merchant scenario / example:**
After installing and configuring the module, you will log into your ShopMania merchant account (or create one). ShopMania will ask you for the "Product Feed URL" or "Data Feed URL." You will then paste the URL provided on this configuration page into the corresponding field on the ShopMania website. ShopMania will then periodically visit this URL to update your product listings on their platform.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My products are not appearing on ShopMania. What should I do?**
A:
1.  **Check the Feed URL:** Ensure you have correctly copied and pasted the exact feed URL from the module's configuration page into your ShopMania merchant account settings.
2.  **ShopMania Processing Time:** It can take some time (hours to a few days) for ShopMania to process your feed for the first time. Be patient.
3.  **Feed Accessibility:** Try opening the feed URL in your web browser. Does it load? Does it show product data? If it shows an error or a blank page, there might be a server-side issue or a problem with the module's generation process. Contact MyPresta.eu support.
4.  **Product Visibility:** Ensure your products are active, in stock, and visible in your PrestaShop store. Products that are disabled or out of stock might not be included in the feed.

**Q: Does this module automatically update prices and stock on ShopMania?**
A: Yes, the feed generated by this module will reflect the current prices and stock levels from your PrestaShop store. ShopMania will periodically re-fetch this feed to keep their listings updated. The frequency of updates depends on ShopMania's fetching schedule, which you might be able to configure in your ShopMania merchant account.

**Q: Can I choose which products are included in the feed?**
A: The basic version of this module typically includes all active and visible products. If you need advanced filtering (e.g., exclude specific categories or products), this would require custom development or a more advanced feed management module. The "Shopmania Integration" module focuses on a straightforward, full-catalog integration.

**Q: I see an error when trying to configure the module.**
A:
1.  **Clear Cache:** Go to **Advanced Parameters > Performance** in your PrestaShop back office and click "Clear cache." Sometimes, old cache files can interfere with module configuration.
2.  **Check Server Error Logs:** If the issue persists, check your server's PHP error logs. These logs can provide specific technical details about what went wrong. You might need to contact your hosting provider or a developer for this.
3.  **Contact Support:** If you're still facing issues, gather any error messages or screenshots and contact MyPresta.eu support for assistance.

**Q: What if my custom theme causes display issues (though this module has no front-office display)?**
A: Since this module has no front-office display, it's highly unlikely to cause any visual issues with your custom theme. Its operation is purely backend, generating a data file.

## 4. Developer & Webmaster Guide (Technical Architecture & Code Map)
This section is strictly for developers, store webmasters, and technical agencies maintaining or extending the store.

### 4.1 Architecture Overview
The `Shopmania Integration` module is a simple, single-file PrestaShop module designed to generate an XML product feed compatible with the ShopMania platform. It follows a standard PrestaShop module structure, primarily utilizing the `install()` and `uninstall()` methods for setup and the `getContent()` method for its back-office configuration, which in this case, simply displays the generated feed URL. The core logic resides within the main module file, responsible for dynamically generating the XML feed when the specific feed URL is accessed. It does not use custom controllers, models, or dedicated template files for its core functionality, relying on direct output for the feed.

### 4.2 Controllers (`controllers/`)
-   **Front-Office Controllers**: None. The product feed is generated directly by the module's main file when its specific URL is accessed, rather than through a dedicated `ModuleFrontController`.
-   **Back-Office Admin Controllers**: None. All configuration (displaying the feed URL) is handled within the `getContent()` method of the main module class.

### 4.3 Core Classes & Models (`classes/`)
-   No custom classes or `ObjectModel` definitions are present in this module. All logic is contained within the `ShopmaniaIntegration` class in the main module file.

### 4.4 JavaScript Assets (`views/js/`)
-   No JavaScript files are included or used by this module.

### 4.5 CSS Stylesheets (`views/css/`)
-   No CSS files are included or used by this module.

### 4.6 Smarty Template Structure (`views/templates/`)
-   No custom Smarty template files (`.tpl`) are used by this module. The `getContent()` method directly outputs the HTML for the configuration page, and the product feed is generated as raw XML.

### 4.7 Database Schema & Hooks Map
-   **Database Tables**: This module does not create any custom database tables. It stores its configuration (if any were needed beyond the feed URL) in the standard `ps_configuration` table, though for this module, the feed URL is dynamically generated and not stored as a configuration value.
-   **Registered Hooks Table**:
    This module does not explicitly register any hooks in the `install()` method for front-office display or action. Its primary function is to respond to a direct URL request for the XML feed. While the feature description mentions "Front-Office Hooks: Header, Columns, Product, or Footer," this is likely a generic description for modules that *could* use these, but this specific module does not implement any visual front-office components. Its integration is purely data-feed based.

| Hook Name | Execution Timing | Technical Purpose |
|---|---|---|
| `displayBackOfficeHeader` | Executed when rendering the Back Office header. | Used to include module-specific CSS/JS for the configuration page (though this module doesn't use any). |
| `displayHeader` | Executed in the `<head>` section of front-office pages. | (Not used by this module for visual output, but could be used for meta tags or scripts if needed). |
| `displayRightColumn` | Executed in the right column of front-office pages. | (Not used by this module). |
| `displayLeftColumn` | Executed in the left column of front-office pages. | (Not used by this module). |
| `displayProductAdditionalInfo` | Executed on the product page. | (Not used by this module). |
| `displayFooter` | Executed in the footer of front-office pages. | (Not used by this module). |

The module's core functionality (generating the XML feed) is triggered when the specific feed URL (e.g., `yourstore.com/modules/shopmania-integration/shopmania-feed.php` or similar, depending on PrestaShop routing) is accessed. This is not a standard PrestaShop hook but a direct HTTP request to a module-specific endpoint.
