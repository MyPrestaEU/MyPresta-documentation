# Voucher Reminder

## 1. Requirements & Compatibility

- **Supported PrestaShop Versions**: PrestaShop 1.5.x, 1.6.x, 1.7.x, 8.x, 9.x
- **PHP Compatibility**: PHP 5.6 - 8.5
- **Hosting Requirements**: Standard PHP extensions (cURL, JSON, OpenSSL) are typically sufficient. Access to set up a cron job on your server is essential for the module’s automatic operation.

## 2. Complete Configuration Walkthrough (Every Setting Grouped by Screen)

### 2.1 Module Configuration Page (Back Office > Modules > Configure)

After installation, the first screen you’ll see is the main configuration page for the Voucher Reminder module. This page is crucial for setting up the core functionality.

**Cron Job URL:**

- **What this setting does:** This displays a unique URL that your server’s cron job needs to call periodically. This URL triggers the module to check for expiring vouchers and send out reminders.
- **Effect of changing this setting:** You cannot change this URL directly. It’s generated by the module. If the cron job is not set up correctly on your server to call this URL, the module will not send any reminders automatically.
- **Recommended value:** Copy this URL exactly and use it to set up a cron job on your hosting server.
- **Merchant scenario / example:** You’ve created several reminder rules, but no emails are being sent. The first thing to check is if you’ve correctly set up the cron job on your server using this URL.

### 2.2 Dedicated Admin Screens & Controller Views

#### 2.2.1 Voucher Reminders Management (Back Office > Modules > Voucher Reminder > Voucher Reminders)

This is where you define and manage the actual reminder rules. Each rule specifies when a reminder should be sent and what email template it should use.

- **Screen Name & Menu Location:** **Voucher Reminders** (under **Modules > Voucher Reminder** in the main PrestaShop menu).
- **Available Actions & Settings:**
  - **List of Reminders:** You’ll see a table listing all your defined reminder rules.
  - **Add New Reminder:** Click the “Add new” button to create a new reminder rule.
    - **Remind (hours before expiration):**
      - **What this setting does:** This is the most critical setting for a reminder rule. It determines how many hours *before* a voucher’s expiration date the reminder email should be sent.
      - **Effect of changing this setting:**
        - *Set to 24:* A reminder email will be sent exactly 24 hours before the voucher expires.
        - *Set to 72:* A reminder email will be sent 3 days (72 hours) before expiration.
      - **Recommended value:** This depends on your strategy. Common values are 24, 48, 72 hours, or even 168 hours (1 week).
      - **Merchant scenario / example:** You want to give customers a final nudge a day before their voucher expires. You would set this to `24`. If you want to give them a week’s notice, you’d set it to `168`.
    - **Title:**
      - **What this setting does:** A descriptive name for your reminder rule, visible only in the Back Office. This helps you identify different reminder rules.
      - **Effect of changing this setting:** Changes the label for this rule in your admin panel. No front-office impact.
      - **Recommended value:** Something clear and descriptive, e.g., “24 Hours Before Expiration”, “Week Before Voucher Expires”.
      - **Merchant scenario / example:** You have multiple reminders. Naming them “1-day reminder” and “3-day reminder” makes it easy to manage.
    - **Email title:**
      - **What this setting does:** This is the subject line of the email your customers will receive.
      - **Effect of changing this setting:** Directly changes the subject line of the reminder emails.
      - **Recommended value:** Something engaging and clear, e.g., “Your [Voucher Code] is about to expire!”, “Don’t miss out on your discount!”.
      - **Merchant scenario / example:** You want the email to stand out in the customer’s inbox. A subject like “Last Chance: Your Discount Expires Soon!” is more effective than a generic one.
    - **Email template file:**
      - **What this setting does:** Specifies which email template file (e.g., `voucher_reminder.html` and `voucher_reminder.txt`) the module should use for this specific reminder. This allows you to have different email designs for different reminder timings.
      - **Effect of changing this setting:** Determines the content and layout of the email sent. If you create a custom template, you’d select its name here.
      - **Recommended value:** Use the default template unless you have specific design needs. If you create custom templates, ensure they are correctly placed in your theme’s `mails` directory.
      - **Merchant scenario / example:** You want a gentle reminder email a week out, and a more urgent “last chance” email 24 hours out. You’d create two different email templates and assign them to their respective reminder rules.
    - **Send reminder:**
      - **What this setting does:** A simple ON/OFF switch to enable or disable this specific reminder rule.
      - **Effect of changing this setting:**
        - *Enabled (Yes):* The module will send emails according to this rule.
        - *Disabled (No):* This rule will be ignored, and no emails will be sent for it.
      - **Recommended value:** “Yes” once you’ve configured the rule and are ready to use it.
      - **Merchant scenario / example:** You’re testing a new reminder rule and want to ensure it’s perfect before activating it for all customers. You’d keep it disabled during testing.
  - **Save Button:** Applies all changes made to the reminder rule.
- **Recommended workflow for daily store management:**
  1. Start by creating one or two reminder rules (e.g., 72 hours and 24 hours before expiration).
  2. Use clear titles and compelling email subjects.
  3. Monitor the “Voucher Reminders History” to see if emails are being sent as expected.
  4. Consider creating custom email templates for different reminder timings to tailor your message.

#### 2.2.2 Voucher Reminders History (Back Office > Modules > Voucher Reminder > History)

This screen provides a log of all reminder emails that have been successfully sent by the module.

- **Screen Name & Menu Location:** **History** (under **Modules > Voucher Reminder** in the main PrestaShop menu).
- **Available Actions & Settings:**
  - **List of Sent Reminders:** A table displaying:
    - **ID:** Unique identifier for the history entry.
    - **Date of email delivery:** When the email was sent.
    - **Reminder:** Which reminder rule (by title) triggered this email.
    - **Customer:** The customer who received the reminder.
    - **Voucher:** The specific voucher code that was reminded about.
- **Effect of changes:** This is a read-only log. You cannot make changes here, but it’s invaluable for verifying the module’s operation.
- **Recommended workflow for daily store management:** Regularly check this history to ensure that reminders are being sent as expected. If you notice gaps or unexpected behavior, this log is your first point of reference for troubleshooting.

#### 2.2.3 Unsubscriptions (Back Office > Modules > Voucher Reminder > Unsubscriptions)

This screen lists customers who have opted out of receiving voucher reminders.

- **Screen Name & Menu Location:** **Unsubscriptions** (under **Modules > Voucher Reminder** in the main PrestaShop menu).
- **Available Actions & Settings:**
  - **List of Unsubscribed Customers:** A table displaying:
    - **ID:** Unique identifier for the unsubscription entry.
    - **Email:** The email address of the customer who unsubscribed.
    - **IP:** The IP address from which the unsubscription occurred.
    - **Unsubscription date:** When the customer unsubscribed.
  - **Add New Unsubscription:** You can manually add an email address to the unsubscription list.
    - **Email of customer:** Enter the email address you wish to unsubscribe.
    - **IP:** (Optional) The IP address associated with the unsubscription.
    - **Date:** (Optional) The date of unsubscription.
    - **Save Button:** Adds the customer to the unsubscription list.
- **Effect of changes:** Customers listed here will no longer receive voucher reminder emails from your store, even if they have expiring vouchers. Manually adding an email ensures they are opted out.
- **Recommended workflow for daily store management:** While customers can unsubscribe themselves, this screen allows you to manually add customers if they contact you directly requesting to be removed from reminder lists. It’s also a good place to monitor unsubscription trends.

## 3. Merchant Troubleshooting & Frequently Asked Questions (FAQ)

**Q: My reminders aren’t being sent. What should I check first?**
A: The most common reason is an incorrectly set up cron job.

1. Go to **Modules > Voucher Reminder > Configure**.
2. Copy the “Cron Job URL” exactly.
3. Log in to your hosting control panel (cPanel, Plesk, etc.) and navigate to the “Cron Jobs” section.
4. Create a new cron job that calls this URL every 5-15 minutes. The command usually looks something like `wget -q -O /dev/null "YOUR_CRON_JOB_URL_HERE"` or `curl -s "YOUR_CRON_JOB_URL_HERE" > /dev/null`.
5. Also, ensure that the individual reminder rules are enabled (“Send reminder” is set to “Yes”) under **Modules > Voucher Reminder > Voucher Reminders**.

**Q: Customers are complaining they’re not receiving reminders, but the history shows they were sent.**
A: This usually points to email delivery issues.

1. **Check Spam Folders:** Advise customers to check their spam or junk folders.
2. **Email Server Configuration:** Ensure your PrestaShop store’s email settings (under **Advanced Parameters > E-mail**) are correctly configured and your server isn’t blacklisted. Using an SMTP server (like SendGrid, Mailgun, etc.) is often more reliable than PHP’s `mail()` function.
3. **Email Template Issues:** Ensure your email templates are valid HTML/text and don’t contain broken links or images that might trigger spam filters.

**Q: Can I customize the email templates?**
A: Yes!

1. The module uses standard PrestaShop email templates. You can find the default template files in `modules/vreminders/mails/en/` (or your language folder).
2. **Best Practice:** Copy these files to your active theme’s `mails/en/` directory (e.g., `themes/yourtheme/mails/en/`). This way, your customizations won’t be overwritten when the module is updated.
3. Edit the `.html` and `.txt` files to match your branding and messaging. You can use Smarty variables available in PrestaShop email templates.
4. If you create entirely new template files (e.g., `my_custom_reminder.html`), you’ll need to select `my_custom_reminder` in the “Email template file” setting for your reminder rule.

**Q: How do I test the reminders without sending them to real customers?**
A:

1. Create a test customer account in your store.
2. Manually create a voucher code for this test customer with an expiration date a few hours or days in the future.
3. Set up a reminder rule with a short “Remind (hours before expiration)” (e.g., 1 hour).
4. Instead of waiting for the cron job, you can manually trigger the cron URL in your browser (though this is not recommended for production).
5. Check the “Voucher Reminders History” and the test customer’s email inbox.
6. Once satisfied, delete the test voucher and reminder rule, and set up your production rules.

**Q: What happens if a customer uses their voucher after a reminder is sent but before it expires?**
A: The module is designed to only send reminders for *unused* vouchers. If a customer uses their voucher, it will no longer be considered “active” and “unused,” so no further reminders for that specific voucher will be sent.
